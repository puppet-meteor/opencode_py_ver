### §0.1 一页摘要

- **问题**：宿主部署形态为平台沙箱、用完即弃，**沙箱无状态化**为目标。因果链：沙箱无状态 ⇒ 记忆必须外置 ⇒ 会话数据须在沙箱存活期内流出。宿主单一 durable 写入路径（事件溯源）不适合承载记忆：L0→L3 提取产物非确定性、不可重放，只能作为**外置派生投影**存在。
- **方案候选**：外挂 TencentDB-Agent-Memory 2.0.3（开源，Node ≥22.16；核心=MemoryCore gateway，可选 MemoryProxy/MemoryPanel/MemoryKnowledge），部署于华为云 CCE（标准 K8s）：CSS（**OpenSearch 引擎线，版本 ≥2.19.0**，候选商用镜像 2.19.0/3.4.0）承载 L0/L1（自写 IMemoryStore 适配器）；OBS（版本化）承载 L2/L3 文件（自写 IStorageBackend 适配器）；DCS（Redis 协议直连）承载分布式锁+任务队列。不进宿主进程、不与沙箱合镜像。
- **接入**：宿主侧走 S3 工具缝——注册三只读工具 memory_search / conversation_search / read_scene，经 registry/invoker/policy 链（审批默认 ask；headless 下 ask=拒绝并 fail-soft 降级）；工具实现用官方 Python SDK tencentdb_agent_memory，契约锚=v2/v3 REST（Bearer+serviceId）。fail-soft 精确口径：失败返回结构化错误载荷、语义层标 unknown、主链路继续；**禁止把 unknown 折叠为「无相关记忆」**。
- **一致性（措辞钉死）**：写路径单点串行（Redis 锁+写确认）；检索可见性按服务语义分别定义（OBS 单对象强一致/多对象与 list 最终一致、CSS 近实时、DCS 异步主备复制）；语义层最终一致（L1 每 5 轮对话、L2 每 5min、L3 每 10min 异步管线）。L1+ 为派生数据，**可由 L0 全量重建**。
- **演进**：P0 单机 PoC → P1 适配器 spike（S-1~S-9）→ P2 产品化能力卡（单租户单副本试点）→ P3 多副本+多租户；P1→P2 为显式立项裁决点。**当前全部未排期。**
- **待裁决/待验证**：U-1~U-7 七项待裁决（含摄入/写路径 U-5、向量交付路径 U-7）；S-1~S-9 九项 spike 登记（可选 S-10）。向量能力交付双轨并列：路径 A「先关键词后补向量」/ 路径 B「一步到位」——同底座同 schema（L1 预留 768 维向量字段）互迁零 schema 成本，不预选。

## §1 目标与非目标 + 替代方案与排除论证

### §1.1 目标
1. **记忆外置且长存**：记忆生命周期独立于沙箱、必须比沙箱存活更久——支撑宿主「沙箱无状态化」目标（沙箱无状态 ⇒ 记忆外置 ⇒ 会话数据在沙箱存活期内流出，流出时点归 U-3）。
2. **跨沙箱与多租户共享**：同一租户/用户的记忆跨沙箱实例可达；serviceId/spaceId 两级隔离（分配粒度归 U-2）。
3. **凭证隔离**：中心侧存储与模型凭证不进沙箱；沙箱仅持有 gateway 访问凭证（Bearer），泄露面收窄到中心入口。
4. **独立升级节奏**：记忆栈（gateway/索引 schema/管线参数）与宿主版本解耦，各自演进互不阻塞。
5. **分层记忆作为外置投影**：L0（原文）→L1（事实）/L2（情节）/L3（语义）提取产物作为宿主事件流的**外置派生投影**——可由 L0 全量重建，不进宿主事件溯源状态。

### §1.2 非目标
1. **不进核心**：不修改 CORE-CONTRACTS/六接缝语义，仅经 S3 既有扩展点（工具注册）接入（详见 §10）。
2. **不做 TS wire 兼容宣称**：本方案为 Python 宿主的外挂能力规划，不宣称与 TS 版 opencode 记忆接口对齐。
3. **不给总工期承诺**：沿宿主 ROADMAP §5 治理口径；本文所有阶段均为候选，当前全部未排期。
4. **不自建主备、不自研记忆管线**：存储 HA 交给托管服务，提取管线沿用上游 2.0.3 既有实现；自研面收敛到两个适配器+接入工具（§5）。

### §1.3 替代方案与排除论证
| 候选 | 排除理由 | 残留考虑 |
|---|---|---|
| **自建记忆**（宿主内建记忆模块/表） | (a) 记忆=第二持久库，吸收进宿主违反单一 durable 写入路径契约；(b) L0→L3 提取非确定性、不可重放，不能作为事件溯源状态；(c) 自研 LLM 提取管线+检索融合栈的成本与质量风险，远高于复用开源成品（2.0.3 含 L0-L3 分层+召回融合+多后端抽象，证据 1/3） | 无——排除性结论 |
| **本地 stdio MCP**（记忆服务随沙箱起停） | (a) 违背沙箱无状态化与「记忆比沙箱存活更久」目标，沙箱销毁即记忆丢失；(b) 多沙箱不共享；(c) 凭证随沙箱分发扩大泄露面；(d) 宿主 MCP HTTP 面为未落地差距（证据 10c），而本需求走 S3 工具缝即可满足 | 若未来宿主引入通用 MCP 外挂治理，可重估接入形态（与本方案工具缝路线不互斥） |
| **其他记忆产品**（通用向量记忆/会话摘要类） | (a) 多数仅覆盖 L0/L1 向量记忆层，无 L0-L3 完整分层管线；(b) 后端绑定（无 IMemoryStore/IStorageBackend 级后端抽象），华为栈适配=深度 fork；(c) 无官方 Python SDK 的候选需自写客户端并承担接口漂移 | 正式选型对比报告（如需）另立票；本文以 2.0.3 的后端可替换性（证据 1/3/5）与官方 SDK（证据 8）为选型基线 |

## §2 架构总图（三层 + 双向数据流 + 网络面与信任边界）

### §2.1 三层拓扑（示意）

```
┌─ 沙箱侧（低信任，用完即弃） ─────────────────────────────────┐
│ opencode-py 宿主                                               │
│   S3 工具缝：memory_search / conversation_search / read_scene  │
│   工具实现：tencentdb_agent_memory SDK（Bearer + serviceId）    │
└──────────── HTTPS/REST（egress 受平台策略约束：U-1/S-7）────────┘
                 │
┌─ CCE 中心服务（高信任） ───────────────────────────────────────┐
│ MemoryCore gateway ×N（无状态多副本；/health 探活）             │
│   REST v2/v3 ｜ 定时提取管线（L1 每 5 轮 / L2 每 5min / L3 每 10min）│
│ MemoryPanel 运维面（可选，部署形态候选见 §3.1）                  │
└──────┬───────────────┬───────────────┬────────────────────────┘
       │               │               │
┌─ 托管存储 ──────────────────────────────────────────────────────┐
│ CSS（OpenSearch ≥2.19.0）→ L0/L1（自写 IMemoryStore 适配器）      │
│ DCS（Redis 协议）→ 分布式锁 + 任务队列                            │
│ OBS（版本化）→ L2/L3 文件（自写 IStorageBackend 适配器）          │
│ LLM / embedding 端点（MAAS）→ 提取管线与向量化                    │
└─────────────────────────────────────────────────────────────────┘
```

### §2.2 双向数据流

**读路径（确定面）**：宿主工具调用 → SDK（Bearer+serviceId）→ gateway REST → 召回（CSS L0/L1 检索三腿：BM25=jieba 预分词 token 字段+whitespace 分词；向量=开源 k-NN；融合=客户端 rrfMerge 兜底或原生 RRF 能力位，详见 §5.1）→（如涉 L2/L3）OBS 取文件 → 返回结构化载荷。失败按 fail-soft 精确口径处理（§4.3）。

**写/摄入路径（候选并列，禁预写，归 U-5 待裁决）**：

| 候选 | 机制要点 | 利 | 弊 |
|---|---|---|---|
| (a) 显式 S3 写工具走审批链 | 新增记忆写入类工具，与读工具同链注册，审批默认 ask（headless=拒绝） | 复用既有 policy/审计链零新增信任面；写入可见可控 | 模型主动写入的噪声/滥用需治理；headless 下 ask=拒绝意味着试点期实际不可写入（须与 U-6 审批粒度联动评估） |
| (b) 宿主侧 SDK 定向推送/事件导出桥 | 宿主在会话事件落地后（或按批）经 SDK 向 gateway 写 L0；可配置脱敏/过滤面 | 摄入自动化、不依赖模型主动性；与宿主事件流时序对齐 | 在宿主侧引入对外写路径的治理边界表述成本（目标为外部库而非宿主 durable 存储，边界措辞须 A 席裁定，见 §10）；导出桥实现面（钩子位置/批量/重试）需专项设计 |
| (c) 网关代理模式 | 中心侧经宿主暴露的只读导出面（或既有同步机制）拉取会话数据 | 沙箱侧零新增写路径 | 依赖沙箱存活期内可被拉取（与 U-3 流出时点强耦合）；宿主当前为客户端形态、无服务端语义（待验证） |

三候选均不预设；决策要件=审批粒度（U-6）、数据流出时点（U-3）、治理边界表述（§10）。**本项登记为 U-5 待裁决，方案书不预写结论。**

### §2.3 网络面与信任边界
1. **信任分界**：沙箱（低信任，不持有中心存储凭证）↔ gateway（唯一入口，持有全量凭证）；凭证单向流动（中心→不出）。
2. **网络路径**：沙箱→gateway 的 egress 能力/路径/白名单由平台侧约束（归 U-1，配套 S-7 实测：延迟 P99/并发上限/断连重试→fail-soft 阈值标定）。
3. **租户面**：serviceId 与 Bearer 凭证绑定；gateway 内按 serviceId/spaceId 做隔离与配额（粒度归 U-2）。
4. **协议面**：仅 HTTPS/REST（v2/v3 契约锚）；无宿主进程内直连存储、无跨层捷径。

| CCE | 节点数×(VM 单价 + CCE 管理单价) + LB | gateway×N + Panel |
| 管线 token | 沙箱数×日均轮次×L1 均次 token×单价 + 定时任务次数×均次 token×单价（L2/L3） | 详见 §11.2 |
| embedding 调用 | 写入条数×均 token×单价（remote 档）；local 档=0（资源折算进 CCE 行） | 路径 B Day-1 起；路径 A 集中于回填窗口 |

> 上表为公式型估算框架，实际数字待 S 系列实测与 P2 试点标定后填充；本文不作总额承诺（§1.2 非目标 3）。

## §4 接入设计（S3 三工具 + 审批 + fail-soft）

### §4.1 工具集（只读三件）
| 工具 | 语义 | 粒度/分页 |
|---|---|---|
| memory_search | 跨层语义召回（L1 为主，融合检索） | topK/游标（候选） |
| conversation_search | 会话/场景级检索（L0 范围） | 同上 |
| read_scene | 读取指定场景完整上下文（L2/L3 文件经引用获取） | 粒度与分页=U-6 待裁决 |

- 注册进宿主 S3 工具缝：registry/invoker/policy 链复用既有实现；审批默认 **ask**。
- 工具实现内部使用官方 Python SDK `tencentdb_agent_memory`（证据 8）；契约锚=v2/v3 REST（Bearer+serviceId）。
- 工具集边界（是否增补写入/遗忘/枚举原语）=U-6 待裁决，与 U-5 摄入路径联动。

### §4.2 ask 的 headless 语义
宿主部署形态为 headless（无交互审批者）。此时 **ask = 拒绝并按 fail-soft 降级**（不挂起主链路、不等待交互）：
1. 若三只读工具保持默认 ask，则在 headless 形态下记忆能力实际不可用——该矛盾**显式登记待裁决**（候选方向：读工具默认 allow+中心侧审计 / 逐会话粒度白名单 / 维持 ask 即接受 headless 不可用，均不预选）。
2. 审批粒度候选（逐次调用/逐会话/逐 space）登记为待裁决，与 U-6 合并处理；利弊展开见 §9.2 U-6。

### §4.3 fail-soft 精确口径（钉死）
1. 读工具失败（网络/5xx/超时/鉴权）返回**结构化错误载荷**（服务不可用），**语义层标 unknown**，主链路继续。
2. **禁止将 unknown 折叠为「无相关记忆」断言**——模型侧收到的载荷必须可区分「服务不可用」与「空结果」。
3. 审计日志须区分 empty-result 与 service-unavailable 两类事件（落 §12 观测面）。
4. 重试策略（次数/退避/熔断阈值）由 S-7 实测定标。

### §4.4 MemoryProxy 路线降级理由
MemoryProxy(:8096) 为透明代理+首轮交互式 session-init（证据 7）：(a) 透明代理绕过宿主侧审计链（工具调用不可见）；(b) 交互式 session-init 与 headless 形态不匹配。故降级为 PoC 备选，不作主路线（多租户面亦见 §7.3 审计双面设计）。

## §5 华为云适配工程四件套

自研面收敛为：适配器×2 + conformance 测试 + E2E smoke + 迁移。工作量表述以 spike 结果为前提再估；任何周期数字仅覆盖适配器本体（不含底座选型/租户治理/平台对接）。

### §5.1 IMemoryStore → CSS（OpenSearch）适配器
- **落点**：IMemoryStore 数据库抽象（证据 3），DbChoice 扩展新 kind（候选命名 opensearch）。
- **检索三腿**：
  - BM25 腿：产品侧 @node-rs/jieba cutForSearch 预分词、空格连接 token 入库（证据 13）——适配器零中文 analyzer 依赖，store 端 whitespace 分词即可。
  - 向量腿：开源标准 k-NN（底座硬性选择标准，CSS OpenSearch 线满足）；CSS 自研向量引擎为备选（API 专有性较强，见 S-5）。
  - 融合腿：客户端 rrfMerge 兜底（nativeHybridSearch=false，零服务端依赖、任意版本可用）**或** hybrid query+RRF pipeline 原生短路（nativeHybridSearch=true；前提=集群内 embedding 模型，因 auto-recall 短路仅传文本，证据 14；TCVDB hybridSearch 形态同构参照，证据 15）。
- **L1 schema 预留 768 维向量字段**（对齐产品 sqlite vec0 默认维度口径），路径 A/B 共用、互迁零 schema 成本。
- **k=60 全链一致**：产品客户端 rrfMerge（RRF_K=60）、TCVDB 服务端 rerank k=60（证据 15）、OS score-ranker-processor rank_constant 默认 60（外源锚点，核验日期 2026-11-09）——排序语义三处同公式同常数。
- BM25 无界分→score 饱和归一化标定（TCVDB 0.33·s/(s+1) 先例）=S-5 实测项。

### §5.2 IStorageBackend → OBS 适配器
- 接口面：对象存储语义约 9 方法（证据 1），现实现 local/cos/rowfs/mongofs——mongofs 证明非 COS 后端可行；OBS=新增实现。
- appendObject 依赖 COS Append API + APPENDABLE_KEY_PREFIXES 守卫（证据 2）→ OBS append 语义差异需 S-2 spike（限制矩阵+限流延迟）；兜底=分块模拟（PUT 拼装）。

### §5.3 conformance 测试（参照上游测试组织）

- 覆盖面候选：CRUD 语义等价 / 检索三腿稳定性（同一语料下 BM25/向量/融合结果可复现）/ 能力位两态行为（nativeHybridSearch true/false）/ append 兜底路径 / 错误映射到工具失败面。

### §5.5 迁移（双写-比对-切换-回收，四步单列）

## §6 HA 与一致性模型

### §6.1 HA 拓扑
不自建主备。gateway 无状态多副本：Deployment ×N + Service/LB + /health 探活；**readiness 含 DCS 连通性检查**（锁/队列不可达时不接新流量）。存储层 HA 由托管服务承担（CSS 多副本分片、DCS 主备、OBS 多 AZ）。

### §6.2 三层一致性（措辞钉死，不作笼统表述）
| 层 | 口径 |
|---|---|
| (1) 写路径 | **单点串行**：Redis 锁+写确认；同 key 写在锁内排序 |
| (2) 检索可见性 | 按服务语义分别定义：**OBS 单对象强一致**/多对象与 list 最终一致；**CSS 近实时**（写后立读需 refresh=wait_for 或读主分片）；**DCS 异步主备复制**（切换窗口可能丢锁丢写，由 S-4 幂等兜底） |
| (3) 语义层 | **最终一致**：L1/L2/L3 异步 LLM 管线（L1 每 5 轮对话、L2 每 5min、L3 每 10min）；多副本下轮次计数语义待验证（S-1）。L1+ 为派生数据，**可由 L0 全量重建**（队列丢失的补偿基线） |

### §6.3 故障域九项 × 三列
（gateway 域按 liveness/readiness 分列两行；恢复动作以重跑/补跑/熔断为主，另含组件级自愈动作。）

| # | 故障域 | 受影响路径（读/写/管线） | 影响层（L0–L3） | 恢复动作 |
|---|---|---|---|---|
| 1a | gateway 挂—liveness（进程级） | 读+写+管线（该副本在途全部） | L0–L3 | 副本自动拉起（无状态，无数据恢复）；在途读→fail-soft |
| 1b | gateway 挂—readiness（DCS 连通性失败） | 读+写（新流量不接入该副本） | L0–L3 | 探活自愈或人工介入 DCS；无需数据面恢复 |
| 2 | Redis/DCS 挂（含主备切换双锁） | 写（锁不可得→停）；管线（队列不可得→停）；无锁读部分继续 | 写=L0/L1；管线=L1–L3 | 任务重跑（幂等，S-4）；切换窗口双锁由锁 token/版本校验兜底（待 S-4 实证） |
| 3 | CSS 抖动（慢查询/分片迁移） | 读（延迟↑→熔断）；写（L0/L1 索引写失败重试） | L0/L1 | 客户端重试+熔断；恢复后自动补齐 |
| 4 | OBS 抖动 | 读（L2/L3 文件取失败）；写（提取产物落盘失败） | L2/L3 | 重试；append 兜底路径切换（§5.2） |
| 5 | LLM·embedding 端点不可用 | 管线（L1/L2/L3 不前进）；BM25 腿不受损；路径 B 查询向量化退化单腿（候选） | L1–L3 | 积压补跑（L1+ 可由 L0 重建）；端点恢复后消化 |
| 6 | 网络分区（沙箱↔中心 / 中心内部） | 沙箱侧读全失败→fail-soft；中心内部按各行组件面 | 全层 | 沙箱侧=语义降级（无需恢复动作）；中心侧组件级自愈 |
| 7 | CNI·egress 策略（沙箱出网被拒/被改） | 读全失败（配置类故障） | 全层（读面） | 策略修正（U-1 登记网络面）；监控告警（§12） |
| 8 | 凭证过期/轮换（沙箱↔gateway、gateway↔存储/MAAS） | 对应路径认证失败→沙箱侧 fail-soft / 中心侧管线停 | 全层 | 凭证热轮换流程（§7.1）；过期前窗口告警 |
| 9 | 升级窗口（gateway 滚动升级 / CSS 版本升级 / 适配器变更） | 滚动期间部分副本摘除；CSS 大版本=专项窗口 | 全层 | 滚动升级+readiness 门控；CSS 升级走迁移四步（§5.5） |

### §6.4 定时任务所有权模型（候选并列，不预设）
| 候选 | 机制 | 利 | 弊 |
|---|---|---|---|
| 集中调度 | 单一调度者（或 K8s CronJob）触发，经 Redis 队列分发 | 触发语义清晰、无重复触发 | 调度者自身单点（需探活+接管） |
| Redis 锁 leader | 各 gateway 副本竞争锁，持锁者执行定时任务 | 无额外组件 | 锁切换窗口重复/漏触发（S-4 实证）；轮次计数语义待验证（S-1） |

决策归 A 席（以 S-1/S-4 证据为输入）；本文不预设。

### §6.5 RPO/RTO 候选值
| 面 | RPO 候选 | RTO 候选 |
|---|---|---|
| L0（CSS） | 快照间隔（候选：每日全量+增量） | 托管服务恢复 SLA |
| L1+（CSS/OBS 派生） | **可由 L0 重建**（RPO=0[派生重建语义；L0 快照 RPO 仍为快照间隔]；重建窗口=管线回放时长） | 重建任务完成时点 |
| L2/L3（OBS） | 版本化+跨区复制候选（RPO=复制间隔） | 版本回滚 |
| gateway | 无状态（RPO 不适用） | 副本拉起（分钟级候选） |

全部为候选值，待 P2 试点标定。

## §7 安全与多租户

### §7.1 认证与凭证
1. 沙箱→gateway：Bearer token（与 serviceId 绑定）；token 分发/轮换流程归平台侧（与 U-1 网络面联动）。
2. gateway→存储/模型：中心侧凭证（CSS/DCS/OBS/MAAS），CCE Secret 注入+命名空间隔离；**凭证不进沙箱**。
3. 凭证轮换：热轮换流程+过期前告警窗口（对应 §6.3 行 8）。

### §7.2 多租户隔离
- serviceId/spaceId 两级隔离；分配粒度待裁决（U-2）。
- CSS 索引隔离策略（U-2 子项，候选并列）：

| 候选 | 利 | 弊 |
|---|---|---|
| 共享索引+serviceId 过滤器 | 资源占用低；运维简单 | 隔离靠查询纪律（过滤器漏带=跨租户泄露风险）；性能互相干扰 |
| index-per-tenant | 物理隔离强；可独立删除（被遗忘权友好） | 索引数×租户增长与 shard 开销；管理复杂 |

- 配额面：IQuotaReporter 抽象位（证据 5）可挂接（候选，待裁决）。

### §7.3 审批与审计
1. 审批默认 ask；headless 语义与粒度候选见 §4.2（归 U-6）。
2. 审计双面：宿主侧=S3 工具链既有审计（读调用）；中心侧=gateway 读写审计日志补位（§12.2）——两段审计以 serviceId+请求标识（候选）关联。

### §7.4 数据生命周期与删除语义
1. 删除粒度：serviceId（租户级）/spaceId（空间级）/scene（场景级候选）；级联顺序=CSS 文档或整索引（U-2 联动）→ OBS 对象含历史版本 → 队列在途任务终止 → 审计日志按合规口径保留或匿名化。
2. 两阶段删除候选：软删（标记+查询过滤）→物理清（窗口期后）；OBS 版本化要求带版本清理。
3. 详细合规面（保留/被遗忘权/PII/备份）见 §13。

## §8 演进路线（P0→P3 + 向量能力交付双轨 + Spike 登记）

**当前全部未排期**；P1→P2 为显式立项裁决点。每阶段含触发/退出/回退三要素，退出条件含量化阈值与失败即止损条款。

### §8.1 P0 单机 PoC
- **触发**：本方案经 A 席立项裁决后排期（当前未排期）。
- 内容：单机（docker compose 级）部署 MemoryCore+sqlite 底座；合成数据优先（真实数据须脱敏并过审批）；三工具经宿主接入贯通。
- **退出判据**（量化候选）：(1) 三工具贯通——全链 200 次请求零未预期错误；(2) fail-soft 演练——注入服务不可用后 unknown 语义正确且审计区分 empty-result/service-unavailable；(3) 一次完整 L0→L3 提取闭环（合成语料，产物可查）。
- **回退**（失败即止损）：任一判据不满足→止损，产出=问题清单+Spike 输入修订，不进入 P1 决策。

### §8.2 P1 适配器 spike（S-1~S-9）
- **触发**：P0 退出判据满足；其中 S-3/S-7（embedding 档位/网络类）不依赖 P0 产出，**可与 P0 并行**。
- **退出判据**（候选）：四件套适配器 conformance 全绿（§5.3）；S-2 OBS append 可行性结论（或分块模拟成本可接受）；S-4 锁丢失率/任务幂等达标；S-5 RRF 端到端+BM25 质量达标；S-9 E2E 闭环。
- **回退**：任一硬性项失败（如 OBS append 不可行且分块模拟成本超限）→登记阻塞项，回方案修订（本文迭代）。

### §8.3 P1→P2 立项裁决点（显式标注）
A 席基于 P0+P1 证据裁决是否产品化；裁决输入=spike 实测数据+成本模型填充（§11）+风险清单更新（§9）。**未过此裁决点不进入 P2。**

### §8.4 P2 产品化能力卡（单租户单副本试点）
- **触发**：P1→P2 立项裁决通过。
- **退出判据**（量化候选）：试点期（候选 4 周）工具错误率低于候选阈值（区分 empty-result/service-unavailable 两类分别计）；召回命中率≥S-6 基线；管线 lag 低于候选阈值；零 P0 级数据丢失事件。候选值：错误率<1%（注入/漏检两类分计）、检索 lag<30min、试点期 4 周（均为候选，待 P2 前标定）。
- **回退**：试点不达标→回 P1 补 spike 或收敛方案（成本/范围裁剪）。

### §8.5 P3 多副本+多租户
- **触发**：P2 退出且多租户需求立项。
- **退出判据**（候选）：副本>1+租户>1 下隔离审计（跨租户读写零穿透）；DCS 主备切换演练通过（S-4 结论复核）；故障域九项抽验演练（§6.3）。
- **回退**：多副本异常→降级单副本运行（读路径不依赖多副本语义）。

### §8.6 向量能力交付双轨（U-7，两轨完整展开、不预选）
两轨同底座（CSS OpenSearch）同 schema（L1 预留 768 维向量字段），互迁零 schema 成本；与 S-3 embedding 档位联动。

**路径 A「先关键词后补向量」**
- Day-1 形态：strategy=keyword + embedding.provider=none（写入不计算向量；schema 仍预留向量字段）。
- 补向量三步：(1) 选定 embedding 档位（S-3）；(2) L0 重建回填重嵌入——L1+ 可由 L0 全量重建、万级记录分钟级、FTS v1→v3 jieba 重建先例（S-6）；(3) strategy 翻转 hybrid——召回走 knn+match 双路客户端 rrfMerge，条件具备（集群内模型）再翻原生能力位。
- 触发：召回质量基线（S-6）不达标或语义召回需求立项。
- 退出：回填完成+双路召回质量达标（recall@k 对照 S-6 基线）。
- 回退：strategy 回翻 keyword（schema 不变，零成本回退）。
- 切换成本与收益：成本=回填窗口（重建+重嵌入时长×数据量）；收益=Day-1 零模型依赖。

**路径 B「一步到位」**
- Day-1 形态：strategy=hybrid + embedding 档位就位（local 离线档为候选起步形态，S-3）；写入时嵌入、向量随写积累。
- 触发：与 P1→P2 立项裁决同步决策（U-7 裁决时点）。
- 退出：语义召回与去重质量达 S-6 基线上限。
- 回退：embedding 档位降级（remote→local）或 strategy 回 keyword（保留已积累向量，schema 不变）。
- 切换成本与收益：成本=Day-1 即引入 embedding 依赖（可用性/延迟/常驻资源）；收益=语义召回与去重质量 Day-1 即达上限、无回填窗口。

## §11 容量与成本模型

### §11.1 容量估算（公式型）
| 项 | 公式（候选） | 说明 |
|---|---|---|
| CSS L0 索引 | 场景数×均原文长度×(1+token 字段冗余系数) | jieba token 字段约等长于原文 |
| CSS L1 索引 | 事实条数×均长×(1+冗余系数) +（启用向量后）条数×768×4B | 向量字段预留；路径 A 启用前不占空间 |
| OBS | 日均场景数×均 L2/L3 文件大小×保留天数×版本化放大系数 | 放大系数=1+版本保留数 |
| DCS | 规格 ← 锁持有率×写入 QPS + 队列深度×消息均大 | S-4 标定 |
| gateway 副本数 | ceil(峰值 QPS×单副本容量冗余系数) | S-7 标定 |

### §11.2 成本驱动因子
1. 管线 token 消耗 ≈ 沙箱数×日均轮次×L1 均次 token + L2 任务次数×均次 token + L3 任务次数×均次 token（定时任务次数=空间数×频次）。
2. embedding 成本（路径 B 持续 / 路径 A 集中于回填窗口）：写入条数×均 token×单价（remote 档）或 CCE 资源折算（local 档）。
3. 检索成本：读 QPS×均延迟 → CSS 规格与副本数。

## §13 数据生命周期与合规

### §13.1 保留策略（候选）
| 层 | 保留 | 依据 |
|---|---|---|

### §13.2 删除与被遗忘权
1. 删除粒度与级联：serviceId（租户）/spaceId（空间）/scene（场景候选）；级联=CSS（删文档或整索引，U-2 联动）→OBS 对象含历史版本→队列在途任务终止→审计日志按合规口径保留或匿名化。
2. 两阶段删除候选：软删（标记+查询过滤）→物理清（窗口期后）；OBS 版本化要求带版本清理。
3. 备份面残留：快照/跨区副本中的删除窗口须在合规口径中显式声明（候选：备份保留期上限）。

### §13.3 PII 与数据处理
1. P0 阶段合成数据优先；真实数据须脱敏并过审批（硬输入口径）。
2. 提取管线 PII 过滤/标注：候选机制，待裁决（不预设）。
3. 区域锁定：数据不出所选华为云区域（候选基线）。

### §13.4 备份恢复
1. CSS 快照（候选：每日全量+增量）；OBS 版本化+跨区复制候选；DCS 无持久业务数据（锁/队列可重建）。
2. **L1+ 由 L0 重建策略**：灾难恢复优先级=先恢复 L0（快照）→管线回放重建 L1+（重建窗口=管线回放时长；RPO 语义见 §6.5）。
