**A 组 · Policy 引擎（tools/policy.py）**
1. PermissionDecision 形状=§5.2 L265 原文（`{effect: allow/ask/deny, reason, action, resources, input_hash, source, expires_at?, audit_id}`）；评估序=宿主硬性 deny/根目录限制优先→项目规则不能放宽宿主限制→剩余匹配规则按来源优先级和规则顺序覆盖→**默认表（L266 原文）：根内 read/glob/grep/ls allow，write/edit/bash/MCP ask**；无人处理 ask 返回 ApprovalUnavailable，绝不变成 allow（L266）。
2. saved 决定语义（L268/L270）：`once` 只批准一个 permission_id+input_hash；`always` 标为"当前进程的本 session"、保存可展示的具体 action/resource 规则、**禁止生成无范围通配许可**；shell 规则绑定完整 command/cwd（L268——S2 落语义面，shell 工具本体归 S5）；`revoke_permission(decision_id)` 追加 py.permission.revoked（L270）；Policy 在使用前检查 expires_at，过期时经提交锁追加 py.permission.expired 后重新求值（L270）；规则撤销/到期不改变已执行结果，但 tool.started 前必须复核有效性（L270）；对 unknown 执行相同输入的重试必须重新 ask，不能复用旧 once/always（L270）。
3. **boot_id 消费（裁定④-3 硬输入）**：每次应用启动生成 boot_id（app.py 装配面铸造）；只激活当前 boot_id 内经宿主批准且未过期/撤销的规则；恢复后 saved 决定保留作审计不自动激活；宿主新的 always 回复产生新决定（L270 原文）。
4. **saved 经同一事件路径写入 permissions 投影（PHASE1-SLIM L96 硬约束）**——py.permission.saved/revoked/expired 事件+S1 投影面复用；**零独立 JSON 权限文件/零 CRUD 面**（r3-slices §4 差异表 4：TS permission/sql.ts drizzle 表 CRUD 不沿用）。

**B 组 · 审批协议+invoker 挂点（tools/invoker.py+registry.py）**
5. 挂点序=§5.1 L259 原文：requested（含原始 requested_name、可选解析后 tool_ref、canonical input/hash）→catalog/schema 校验→**成功再走 policy/审批 → started 提交确认 → adapter 执行 → 结果限额/归一化 → finished 提交**；输入在校验/审批后不可变（L261）；PermissionPolicy 注入 Invoker（L257）；只有 Invoker 的事件回调可提交，adapter 不拿 Store/DB（L259）。**py.permission.requested/replied/closed 的生产者全部经 Invoker 事件回调提交（裁定④-1 硬输入：真实 Policy 链生产者——S1 的手工注入测试面保留原样，本切片新增真实链测试，不回头改 S1 测试）**。
6. 审批协议（L268 原文）：requested→（replied|closed|expired），默认 300 秒；**策略直接 deny 不伪造宿主回复；实际 reject 才写 py.permission.replied**；审批未连接、超时/取消写 py.permission.closed（未连接用 cancelled+ApprovalUnavailable），pending 工具结束为 cancelled/not_started；迟到回复拒绝，不能覆盖 closed。
