| 问题 | 源码证据及实际范围 |
|---|---|
| 能否零 LLM 执行 | 可以。引擎层可构造固定 `StepDef[] + PipelineMeta + input_vars` 直接调用 `PyDAGEngine.execute`；构造器的 reflection/extract/call/param_fallback 四个 LLM hook 默认均为 `None`（`relay/dag_engine/engine/pydag_engine.py:597`，execute `:929`）。前提：计划不含需要 LLM 的参数/节点，工具内部也不调用 LLM。 |
| 固定 Skill 是否天然零 LLM | **不能保证**。参数解析失败可调 LLM fallback（`:2481`）、工具失败可触发 hook（`:2558`）、输出抽取不足有 hook（`:2665`）；高层还有自然语言路由和参数抽取（`relay/dag_engine/README.md:15`）→ 严格模式必须在验证期显式拒绝这些路径（裁决项 3）。 |
| 核心数据接口 | `StepDef` 有 tool/params/output/depends_on/condition/extract/transform/for_each/parallel_map/poll/fallback；`ParamDef` 含 literal/ref/template/context_bundle/llm_call（`dsl/pydag/step_def.py:31`）。 |
| 分支 | 条件为假时跳过步骤；条件解析不用 `eval`，支持有限比较与 and/or，不是任意 Python，也不是完整子图 switch/循环语言（`pydag_engine.py:1431`、`dsl/condition_eval.py:43`）。 |
| DAG/并行 | `depends_on` 决定 DAG 边，无显式依赖走线性拓扑；有 fan-in 接线。`parallel_map` 用 Semaphore+TaskGroup，按输入索引收集结果（`:1109`、`:4991`）。结果数组保序不意味着外部副作用发生顺序固定。 |
| 循环与轮询 | `for_each` 顺序执行列表元素；`poll` 是有界工具轮询（间隔、次数/时长、done/fail 条件）（`:4795`、`:5372`、`step_def.py:75`）。不能据此宣称支持通用嵌套多步骤 while 子图。 |
| 数据绑定 | 输入/前序结果引用、字段抽取、严格模板、受控 compute transform；`builtin.compute` 跳过外部工具调用（`step_def.py:31`、`pydag_engine.py:2439`）。 |
| 静态门禁 | 校验未知工具、缺失必填参数、悬空引用、环及输出约定误用；工具/schema 必须传入才能执行相应门禁（`dsl/pydag/quality_gates.py:42`）。 |
| 错误传播 | 失败依赖确定性阻断下游，缺引用不猜值；失败分类+稳定错误码；空输出可尝试**声明的**备用工具（`:1410`、`:2646`）。LLM reflection 的 retry/abort 不是零 LLM 重试策略。 |
| 断点恢复 | 核心执行 `graph.compile()` 未注入 checkpointer，每次构造新的初始状态后 `ainvoke`（`:993`）——不能从"使用 LangGraph"推断已具备任意步骤崩溃恢复。外围 durability 端口（artifact/control-plane/snapshot/repair-evidence/outbox）缺省配置为 off（`relay/runtime/execution/durability.py:52`）。两者不是同一项保证。 |
| 幂等和副作用 | `relay/dag_engine/mcp/side_effects.py:1` 明确仅分类证据并报告，不自行阻止执行；不能承诺任意外部工具 exactly-once。业务写操作的幂等键、超时后核对和恢复策略需专门定义（→ M8-R 子卡片）。 |

"确定性"首先指控制逻辑无需 LLM 决定；网络响应、时钟、并发和外部服务仍可能改变结果。严格可回放还需版本固定、活动结果记录和受控的恢复语义。

**不宜整搬的证据**：`pydag_engine.py` 约 7472 行（含身份解析/拓扑/告警/指标归一化等领域逻辑）、`tool_dispatcher.py` 约 2123 行（关联工具观测和审计库）；框架整体还含意图识别、NL→DSL 编译、动态规划、在线修复、发布和 Studio，远大于固定流程执行所需（`relay/dag_engine/README.md:35`）。核心依赖 LangGraph/OpenAI/httpx/PyYAML/JMESPath/sqlglot/portalocker（`relay/dag_engine/requirements.txt:1`）——M8 只取执行语义与校验规则，不整搬框架；是否引入 LangGraph 由 spike 的图语义/恢复方案决定，不因参考项目使用而顺带承担。

**值得参考的最小设计**（对上述证据的提炼，供裁决与卡片采用）：WorkflowSpec 只需版本/输入 schema/步骤 id/工具名/明确引用/依赖/条件/输出，JSON/YAML 只是序列化格式，不新增一门复杂语法；compile/validate 产出**不可变执行计划**；所有工具调用经宿主已有 invoker，权限和事件由宿主管理；缺参直接报告不猜值；显式 llm 节点+预算，严格模式拒绝一切 LLM 节点/回退，规划/修复放独立 authoring/repair 流程；跨进程恢复单独实现 run/step 状态与写操作幂等协议，不把数据库审计日志当恢复引擎；验收至少包括零模型调用、相同活动结果下控制路径一致、失败后写操作不被盲目重放。
