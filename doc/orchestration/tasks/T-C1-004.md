【任务】
1. `src/opencode/storage/store.py`（SessionStore 公共门面，S6 唯一提交入口）——commit 路径按 §3.2 严格顺序：
   a. 写事务内读 `H = COALESCE(MAX(events.seq), 0)`（范围只含该 session 已提交行）；
   b. **写入门禁先于幂等查询**：sessions.status 为 read_only_diagnostic → SessionReadOnly（不进入幂等判定；注意语义=已提交事件的"重放读取"仍可用，拒绝的是 commit 入口而非数据）；
   c. **幂等判定先于 expected_seq**：按 EventBatch.id+事件 ID+内容对比——同批次完全重试（含 expected_seq 落后）返回原 DurableEvent 列表，不推进 H/A、不重投影、不通知；"已提交但没收到返回"的重试成功；混合旧/新 ID、同 ID 不同内容、全新批次 seq 冲突 → IdempotencyConflict/Conflict 明确拒绝；
   d. 全新事件：核对 expected_seq（不等→Conflict）/归属/版本；
   e. 分配连续 seq=H+1..H+n → 插入 events → 调注入 projector（同事务）→ commit → 返回 DurableEvent 列表；
   f. 水位不变量（§3.2 L163-165）：健康 A=H；提交 n 个事件原子推进 A=H+n；发现 A≠H、seq 间隙/重复/非法 seq → **StorageCorrupt**（不是调用方 Conflict，不得通过改 expected_seq 续写）；sessions 行缺失语义按契约 L163（已有日志却缺行=读模型缺失，不是新建会话）——歧义写未决问题，不自行发明。
2. `src/opencode/storage/txn.py`（TransactionWriter，S4 私有）——**§3.2.1 隔离入口**：会话锁下短事务持久化 sessions.status=read_only_diagnostic + 脱敏 diagnostic（reason、可定位时的首个坏 seq/event_id、发现时 applied_seq）；先整体回滚再独立短事务落诊断；诊断写入不产业务事件、不推进 seq/applied_seq；**不触碰任何通知接口**（无 Bus 依赖——"诊断写入零 Bus 通知"本切片以结构保证+测试断言 store/txn 无 Bus 依赖，真实订阅者断言归 S5/S7 联测）；per-session asyncio.Lock + 进程内写事务串行（单 writer OS 锁已由 db.py 承担）。
