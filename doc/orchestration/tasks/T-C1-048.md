## 3. 写面（恰 4 路径）

### A1 新增 `tests/integration/_maas_real_config.py` — 配置桥 helper

纯 stdlib + 全类型注解（mypy `disallow_untyped_defs` 面）。解析序:

1. **env 模式**: `OPENCODE_PY_MAAS_BASE_URL` / `OPENCODE_PY_MAAS_API_KEY` / `OPENCODE_PY_MAAS_MODEL` 三者任一存在即进入 env 模式，且三者须齐（缺任一=不可用，不与文件源混掺）；
2. **文件模式**: 配置目录 = `$XDG_CONFIG_HOME/opencode`（设了的话）否则 `Path.home()/.config/opencode`；`opencode.json` 与 `opencode.jsonc` 双读合并（jsonc 剥 `//` 注释与尾逗号后解析；jsonc 键浅覆盖 json）；
3. provider 块 = `OPENCODE_PY_MAAS_PROVIDER`（默认 `gateway`）；`baseURL`/`apiKey` 取自该块；模型 = `OPENCODE_PY_MAAS_MODEL`（若设）> 块内 `models` 映射首键。

- 不读 auth.json；apiKey 仅在内存经 argv 传 in-process `main()`，不打印不落盘。
- 输出 dataclass: `base_url` / `api_key` / `model` / `source`（`"env"`|`"config"`，用于 skip 理由与证据行，不含真实值）。
- 不可解析（无 env 且无配置文件 / 无该 provider 块 / 字段缺 / `models` 空）→ 专用异常 `MaasRealConfigUnavailable`（消息只写缺什么，不含已读到的任何真实值）。

### A2 新增 `tests/integration/test_maas_real_session.py` — 双场景（恰 2 个测试函数）

公共面:

- `@pytest.mark.maas_real` + **双重门**: `OPENCODE_PY_MAAS_REAL=1`（严格等于 `1`）且 helper 可解析，否则 `pytest.skip`——两条理由分开写实（opt-in 未开 / 配置不可用）→ 默认套件与 CI 恒 skip。
- argv 由 helper 值组装: `--db <tmp_path>/maas-real-*.db`、`--base-url`、`--api-key`、`--model`、`--context-limit`（选值依 §2.3 核实结论）、`--timeout-s 180`。
- **断言纪律**: 只断结构事实（exit code、`runs.status`、events 类型/计数、text part 非空/含固定标记词）——不断言原始 endpoint/model/key 字符串相等（防失败回显泄露）。标记词=固定非敏感常量（如 `quokka-7f3a`）。
- `main()` 返回后立即 `capsys.readouterr()`；预算选值与权限面结论写模块 docstring。

场景 1 文本回合: `main(argv, lines=["<固定短 prompt>", "/exit"])`；断言 exit 0 + run completed + assistant 消息存在非空 text part（长度>0，不 pin 原文）。

场景 2 工具真执行回路: 测试先在 tmp_path 写目标文件（内容=固定标记词）；`--project-root <tmp_path>` 使读取落项目根内；prompt 明确要求先用 read 工具读该文件、再回答其中的标记词；断言 = tool_call 事件（工具名以源码为准 C 席亲核，read/fs.read 形）+ tool result 事件 + 终态 completed + 最终文本含标记词。**C 席须亲核 permission projector 的 auto-allow 面**（`--project-root` 指向 tmp_path 是否使 in-root read 免审批；若会触发审批 UI，改选默认放行的最简只读路径并把结论记入 docstring——禁止测试卡在审批面）。
