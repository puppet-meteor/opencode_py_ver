## ② 设计判定

- **包结构**：`src/opencode/watcher/`（新建，恰两文件）=`__init__.py`（61 行：extras 守卫+公共面）+`service.py`（243 行：服务核心）。**httpapi 先例同形镜像**：`WatcherExtrasMissingError(StoreError)` 携 `code = CoreErrorCode.UNSUPPORTED_CAPABILITY`（§8 闭合注册表既有 code，零新 code）；`_require_watcher_extras()` 模块级延迟 import 门（`import watchfiles` 失败→守卫错，消息含 `pip install 'opencode-py[watcher]'` 指引+core 不受影响声明）；docstring 载明 core 永不 import 本包；尾部 `from opencode.watcher.service import ...`（`# noqa: E402`，httpapi 同形）。
- **服务核心（`WatcherService`）**：构造 `roots: Sequence[Path]`（宿主注入，本票不接 ConfigLoader/SessionService/App 装配——零 src 既有文件触碰）+去重/合并参数（缺省 `debounce_ms=250`、`merge_window_s=0.5`、`queue_size=64`，契约「阈值归实现切片」条款承载；构造校验空 roots/非法参数 fail-fast）。生命周期=异步上下文管理器：`start` 起 pump+merger 两任务；`stop`/`__aexit__` 收口（**幂等性由活任务态派生**——「未启动先 stop」不毒化后续 watch，pump 先亡时 merger 也不遗漏）；`start` 不可重入。
- **去重/合并两层**：库级 `awatch(debounce=..., step=50)` 组批 + Python 侧静默窗合并（首个待并批后 `merge_window_s` 静默窗内后续批全并入一个 `ChangeNotification`，窗内 N 变更→1 通知）。
- **通知面（裁定①承载）**：宿主唯一消费者=有界 `asyncio.Queue[ChangeNotification]`（`maxsize=queue_size`）；溢出丢弃并计 `dropped_notifications`（「提示丢失无害」）；载荷=`ChangeNotification(paths, event_types)` 纯数据（frozen dataclass）。**零状态变化结构面**：`service.py` 全路径零 opencode import（Bus/日志/快照/审批面结构性不可触），守卫面仅 contracts.errors（code 注册表）+storage（StoreError 基类）。
- **背压面**：pump→merger 内部队列亦有界（`_MAX_RAW_BATCHES=256`，溢出计数）；merger 从不阻塞（emit=put_nowait），风暴下通知数受合并窗约束。
