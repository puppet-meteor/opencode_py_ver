## ① 改动清单

**`src/opencode/bus/eventlog.py`**（新增，DB 耦合的 durable 读取面——契约 §4 L222-238 字面；模块 docstring 注明架构定位：与 `bus/bus.py` 的零 DB 断言不冲突，S5 结构断言只钉 `bus/__init__`+`bus/bus`；不从 `bus/__init__.py` re-export，使用方直接 `from opencode.bus.eventlog import ...`）
1. `EventCursor = {session_id, seq}`（0=日志之前）、`EventPage = {items, next_cursor, has_more}`、`Synced(cursor)` marker、`LogItem = DurableEvent | Synced`（TS `log.synced` L879-884 对应）。
2. `EventLog.read(session_id, after=None, limit=100)`：seq>after.seq 的 durable，None=本 session seq 0；limit 1–1000 越界**钳制**（bool/非整数→ValueError）；next_cursor=最后一个 item 的 seq，空页保持输入 cursor；未建 session→`NotFoundError`；`InvalidCursorError` 三类=cursor.session_id 不符/seq 为负/seq 超过 H（明确报错不空等）；**H=COALESCE(MAX(events.seq),0) 非 applied_seq**。坏页语义（T-A-002 终裁逐项）：按原 seq 连续解码，首个坏行**整页** `StorageCorrupt(retryable=false)`——无半页、next_cursor 不推进、同 cursor 重试同错、read 失败 cursor=输入 after（None→0）；details 五字段（脱敏 reason/session_id/first_bad_seq/first_bad_event_id/last_confirmed_cursor），不含坏行原文；TS `readAfter` L809-827 跳过并前进 raw seq 的行为**不沿用**，未知版本/类型同样 fail closed。
3. `EventLog.follow(session_id, after=None) -> _Follow`（同时实现 async context manager 与 async iterator，进入后对象即迭代器）：①**先注册 wakeup**（bus 订阅 + drain 任务把事件泵入单槽 `asyncio.Event`，重复唤醒合并；drain 失败只损失唤醒、置最后一次信号后停）**再**在短读事务捕获 H——该读取即初始游标验证与补读窗口的线性化点；②分页补读 after.seq<seq<=H，发**一次** `Synced(EventCursor(session_id, H))`；③此后始终查 seq>last_seq，**Bus 只当唤醒信号**（payload 永不回放），poll_interval≤1s 轮询兜底（丢通知退化为轮询节奏，正确性不依赖 bus）；④同一连接 seq 严格递增（违反→`non_increasing_seq` fail closed）。`__aenter__` 失败自注销 wakeup（不依赖 `__aexit__`）；正常/异常/取消退出均注销。follow 坏页=已 yield 健康事件保留，随后抛 StorageCorrupt 终止，**不发越过坏点的 Synced**（坏点在初始 H 之后时已发的 Synced 只确认旧窗口，无带外 marker）。只重放 durable，ephemeral 仅作唤醒（§4 L238）。
4. 读门禁：session.status=read_only_diagnostic（经只读 repo 读取）→ read/follow 在**任一 cursor** 都 `StorageCorrupt(reason=session_read_only_diagnostic, retryable=false)`——不能凭更大 after 或类型过滤绕过（§3.2.1：typed 读取面 fail closed，读模型仍可查）。
5. 解码助手 `_json_column`/`from_epoch_ms`/`REASON_STORED_DECODE_FAILED` 只读 import 自 `opencode.storage.txn`（docstring 注明跨模块私有 import 取舍，见 ③-1）。

## ③ 未决问题

1. **解码助手跨模块私有 import**（`_json_column`/`from_epoch_ms`/`REASON_STORED_DECODE_FAILED` 自 `storage/txn.py`）：任务书明示"不做共享 codec 抽取"，按要求保留 import 并在 docstring 注明。遗留审查点：EventLog read 路径与 `TransactionWriter._decode_stored` 的逐字节一致目前靠镜像约定（同一批助手），后续可裁决是否抽 `storage/codec.py` 单点化。
2. **read 路径发现的坏页不写隔离**：EventLog/repos 检出坏页只抛 `StorageCorrupt(isolate=true)`，从不自行写 §3.2.1 隔离表（EventLog 无权写表）；把读取面检出接入隔离/处置属 S8，接线点需调度器确认。
3. **sessions 行缺失但 events 存活**：follow 只在"无 sessions 行且 H==0"时报 NotFound；有日志无 sessions 行时照常补读（契约只对未建 session 钦定 NotFound）。repos 侧对此已 fail closed（`sessions_row_missing_with_log`）；EventLog read/follow 是否同样门禁待裁决，当前最保守读法=照常读日志。
4. **`NotFoundError`/`InvalidCursorError` 落位 `storage/repos.py`**：避免为两个 wire 错误单开 errors 模块；若审查倾向独立模块或移入 contracts，纯移动无行为变化。
5. **anext 级取消语义**：契约 §4 未定义逐项取消；当前读法=对该次 pull 的取消（如 `wait_for` 超时）会关闭整条 follow 连接（生成器被 CancelledError 终结），context 退出照常注销 wakeup。未实现 per-pull shield 保活（消费方用 `async for`，或避免对流中途做超时探测）；若裁决需要"超时不断流"，改 `_Follow.__anext__` 为 shield+pending 单点即可。
6. **工程选值非契约值**：内部页大小 512（TS `logReadPageSize` L207 对应）、`poll_interval` 钳制 ≤1s（默认 1.0）、limit 钳制 1–1000（read 与 `repos.messages` 同界）。
7. **无契约矛盾**：与 §4 L222-238、§3.2.1、r1-slices §2 R1-S6 L121-132 逐条对齐；TS 差异（readAfter 跳过前进不沿用、subscribeDurable 的 `PubSub.sliding(1)`→单槽 Event+轮询兜底）均按 T-A-002 终裁与任务书既定映射执行。
