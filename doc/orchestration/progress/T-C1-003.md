## ① 改动清单

**`src/opencode/storage/db.py`**（新增）
1. `open_database(path, *, mode="create") -> Database`：三种 open 模式 `OpenMode = Literal["readonly", "create", "readwrite"]`（对应 TS `nativeLayer` L87-91 open flags：`readonly` 只读、`create` 读写+缺文件即建（TS `create ?? true`）、`readwrite` 仅读写已存在文件）。`readonly` 经 sqlite URI `file:...?mode=ro&uri=true` 只读打开；`readonly`/`readwrite` 对缺失文件先抛 `DatabaseNotFoundError`（不碰锁、不建目录）。
2. **writer 锁先于 DB 打开**：`WriterLock` 对 DB 同目录 `writer.lock`（0600）做 1 字节区域锁——Windows `msvcrt.locking(LK_NBLCK)` / POSIX `fcntl.flock(LOCK_EX|LOCK_NB)`，逐字复用 R0-B 探针已验证方案（`tools/r0/platform_probe.py`，证据 `doc/evidence/r0/platform.json`）。第二 writer → `WriterLockHeldError`（R0-B 结论复用，按任务书**不重测**）。`readonly` 不取锁。引擎创建失败时锁在 `except BaseException` 中回滚释放。
3. `Database` 句柄：`close()` dispose 引擎后释放锁（顺序固定），幂等；`async with` 上下文退出即关——对应 TS close finalizer（L92）。
4. **PRAGMA（CORE-CONTRACTS §5）**：经 `event.listens_for(engine.sync_engine, "connect")` 对**每条池化连接**执行 `foreign_keys=ON`、`busy_timeout=5000`（`BUSY_TIMEOUT_MS`）；writer 连接再执行 `journal_mode=WAL`（`readonly` 连接写不了 journal mode，跳过——文件一旦被 writer 开过即为 WAL）。
5. 错误类型：`StorageError(RuntimeError)` 基类 + `WriterLockHeldError` / `DatabaseNotFoundError`（上层切片再映射 CoreError）。

**`src/opencode/storage/migrations/env.py`**（新增）：迁移用**同步**引擎（r1-slices §4 #6），运行时才用 async——SQLite 文件级兼容。URL 解析优先级：`-x db_path=<文件>`（`Path(...).as_posix()` 转换，Windows 路径安全）> `alembic.ini` 的 `sqlalchemy.url`；两者皆无 → `RuntimeError`。offline（`--sql`）与 online 两模式均实现。

**`src/opencode/storage/migrations/versions/0001_initial.py`**（新增）：五表最小 schema，列名以契约 §3.2 逐列为准：
- `events`（id PK/session_id/seq/type/version/created INTEGER epoch ms/data JSON/metadata JSON/batch_id/batch_ordinal/dedupe_key 可空）；命名 unique index ×3：`events_session_seq_uq(session_id,seq)`、`events_session_batch_uq(session_id,batch_id,batch_ordinal)`、`events_session_dedupe_uq(session_id,dedupe_key)`。**无独立 sequence 表**（seq=事务内 max+1 分配，Python 侧差异；TS `EventSequenceTable` 不移植）。**events 不带 FK**——见 ③-1 最保守读法。
- `sessions`（session_id PK/status/active_run_id 可空/config_snapshot JSON 可空/snapshot_hash 可空/applied_seq INTEGER NOT NULL default 0/diagnostic JSON 可空；§3.2.1 最小诊断记录三项可空成立）。
- `messages`（session_id/message_id/seq/data JSON；unique(session_id,message_id)）；`tool_executions`（session_id/execution_id/run_id/step_id/message_id/tool_call_id/input_hash/state；unique(session_id,execution_id) + unique(session_id,step_id,tool_call_id)）；`permissions`（session_id/permission_id/decision_id/execution_id/action/resources JSON/input_hash/scope JSON/expires_at/state）。三张读模型表 FK→`sessions.session_id` ON DELETE CASCADE。

## ③ 未决问题

1. **events 无 FK（任务书与契约冲突，最保守读法实施）**：任务书 §3.2 events 描述含"归属 FK cascade"，但若 events→sessions FK CASCADE，删 sessions 行（读模型重建）会连带摧毁 events 日志——与契约 §3.2.1"sessions 行缺失而 events 保留"及 §3.3 验收 C（读模型重建）直接矛盾。已按最保守读法：**events 零 FK**（持久日志独立于读模型存活），FK CASCADE 落在 messages/tool_executions/permissions→sessions。测试钉死 `_foreign_keys(db, "events") == []`。待 A/B 裁决，若判 events 仍需 FK 再改（会同时触碰 §3.3 重建验收）。
2. **§3.2 unique 约束实现为显式命名 unique index**：SQLite 内联 UNIQUE 生成不可寻址的 `sqlite_autoindex_*`；命名 unique index 语义等价（UNIQUE 约束=唯一索引）且可被后续修订引用、被集成测试断言。迁移 docstring 已注明理由。
3. **sandbox 拒绝默认 pytest 临时根 `$TMP/pytest-of-lyu`（WinError 5，连列举都拒）**：`tests/integration/conftest.py` 设 `PYTEST_DEBUG_TEMPROOT=$TMP/opencode/pytest-tmp`（`setdefault`，pytest 在首次用到 `tmp_path` 时才懒解析根目录，时机在 conftest 导入之后，故生效）。标准 `tmp_path` fixture 语义不变（每测试独立目录）；默认根可用的机器上此重定向无害。若调度器认为该 conftest 不该长期存在，需裁决（目前它是 sandbox 内跑 integration 的唯一通路）。
4. **`script.py.mako` 未创建**：任务书授权文件枚举不含它；修订 0001 为手写（非 `alembic revision` 生成），升级流程已验证无需模板。未来若要求 CLI 生成修订，需补授权后添加。
5. **`alembic.ini` 占位 URL 的副作用**：`sqlalchemy.url = sqlite:///./opencode.db`（cwd 相对）——裸跑 `alembic upgrade head`（不带 `-x db_path`）会在 cwd 创建 `./opencode.db`。全部集成测试显式传 `-x db_path`。若调度器要求无 `-x` 即 fail-fast，删掉该键即可（`env.py` 会对无 URL 抛 `RuntimeError`）。
6. **permissions 最小列集的取舍**：§3.2 permissions 描述为"input_hash/scope/expiry/terminal state"；实现按 `py.permission.requested`/`py.permission.saved` wire 数据投影出 10 列（列清单见迁移 docstring）：除 `session_id`/`state` NOT NULL 外均可空——`py.permission.saved` 数据不含 input_hash 故 nullable；无 unique 约束（契约未列）。请调度器对照 §3.2 逐列核。
7. **sync 迁移 + async 运行时组合结论（r1-slices §4 #6，任务书第 4 条）**：env.py 同步引擎跑迁移、运行时 `open_database` 的 async aiosqlite 引擎，同一 DB 文件、Windows 路径下验证：async 引擎在 sync 迁移所建 schema 上写入成功（INSERT events + commit + count 断言）、PRAGMA 三项生效、WAL 持久化到文件、dispose 后新 writer 可再开。**结论：文件级兼容，组合无坑**。另注：SQLAlchemy 2.x 必须装 `[asyncio]` extra（greenlet），纯包 async 引擎运行时报错——已按此写入依赖。
