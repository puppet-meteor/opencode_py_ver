## ① 改动清单

**`src/opencode/storage/store.py`**（新增，公共面）
1. `EventBatch`（frozen dataclass）：batch id + 有序 drafts 元组 + 可选 `dedupe_key`（批级，整批同值写入每行 `events.dedupe_key`，跨批受 `unique(session_id, dedupe_key)` 约束）。
2. `Projector` Protocol（§3.2 注入缝）：`async apply(connection, event)`——真实读模型投影器是 R1-S4，本片仅注入 fake；apply 在插入的同一写事务内按序逐事件调用，须推进 `sessions.applied_seq`（store 提交前复核 A=H+n，违者整单回滚），抛异常即整单回滚。
3. `SessionStore(engine, *, projector, registry=None)`（registry 默认 `default_event_registry()`）+ `commit(session_id, batch, expected_seq) -> list[DurableEvent]`：唯一提交接口，全部委托私有 TransactionWriter；无 Bus 依赖（R1-S5，测试以 AST 导入扫描结构性钉死）。

**`src/opencode/storage/txn.py`**（新增，S4 私有缝；`TransactionWriter` 不进 `__init__` 导出）：按 §3.2 严格顺序执行
1. 锁：per-session `asyncio.Lock`（get-or-create，注册表 R1 不设上限）+ 进程级写锁；跨进程由 `db.py` 的 OS 文件锁串行。
2. 单写事务内顺序：读 `H = COALESCE(MAX(events.seq), 0)`（连同 COUNT / COUNT DISTINCT(seq) / MIN(seq) 供不变量分类）→ **写闸门**（内存隔离集 → `sessions.status`：`read_only_diagnostic`→SessionReadOnly、`cleanup_failed`→LifecycleCleanupFailed、`closed`→SessionClosed、未知 status→StorageCorrupt；sessions 行缺失且 H>0 → 读模型缺失→StorageCorrupt；首次创建（无行且 H=0）豁免）→ **幂等**（键=batch.id+事件 id+内容，先于 expected_seq：整批重放（含过期 expected_seq）返回原事件、零再投影/零 H·A 推进；跨会话 id / 新旧混合 / 同 id 异内容 → IdempotencyConflict，绝不重投影）→ **H/A 不变量**（A≠H、seq 空洞、重复、非法 seq → StorageCorrupt 而非 Conflict）→ **expected_seq≠H → Conflict**（等值语义，无"追平"）→ **归属/版本**（draft.session_id 须等于会话；(type, version) 须在注册表）→ 连续 seq `H+1..H+n` 插入（IntegrityError→IdempotencyConflict，兜住批内重复 id 与 dedupe 冲突）→ 注入投影器同事务逐事件 → 复核 `A = H+n`（违者 `isolate=False` 只回滚，前置状态健康故不隔离）→ commit 返回 `list[DurableEvent]`。
3. §3.2.1 隔离入口：业务事务**完全回滚后**，独立短事务先 `UPDATE` 既有 sessions 行（**保留** applied_seq/快照，仅改 status+diagnostic），无行则 `INSERT` 最小诊断记录（applied_seq=0，config/active_run_id/snapshot_hash 均空）；净化诊断 = `{reason, first_bad_seq(可定位时), first_bad_event_id, applied_seq(发现时)}`；诊断写零业务事件、零 seq/applied_seq 推进、无 Bus 依赖。持久化失败 → 内存写闸门仍生效 + `IsolationPersistFailedError`（原 StorageCorrupt 照常抛给调用方，隔离失败经异常链保留）。
4. 错误类型：`StoreError(StorageError)` 基类（携带 §8 `CoreError` wire 形状，子类各自钉死 code，S6/S7 免再裁量）+ `SessionReadOnlyError`/`SessionClosedError`/`LifecycleCleanupFailedError`/`StoreValidationError`/`ConflictError`/`IdempotencyConflictError`/`StorageCorruptError`(isolate 标志)/`IsolationPersistFailedError`。
5. `epoch_ms`/`from_epoch_ms`：`events.created` INTEGER epoch ms ↔ datetime（毫秒精度）互转；`_json_column`：`text()` 行取回的 JSON 列按驱动原样（字符串）解析后再比较/解码。

**`src/opencode/storage/__init__.py`**（修改，仅扩展导出）：+`SessionStore`/`EventBatch`/`Projector` + 上列 9 个错误类型（`__all__` 按 RUF022 排序）。

2. 整批重放：过期（0）与正确（2）expected_seq 均返回原事件（含类型化 data 往返），零再投影、零行新增、零水位推进。
3. 幂等冲突三类：新旧混合 / 同 id 异内容（同 batch id）/ 跨会话 id → IdempotencyConflict（§8 code 与 details 断言），零持久化。

## ③ 未决问题

1. **读模型缺失的歧义**（sessions 行缺失而 events 在）：任务书标注"歧义 → 未决问题，最保守实现"。已按最保守读法：判 StorageCorrupt + §3.2.1 隔离 + INSERT 最小诊断记录（A=0）；新会话首次提交（无行且 H=0）豁免。待 A/B 裁决。
2. **空批次**：任务/契约未定义。已按 ValidationError 拒绝（"零事件提交"会使 A=H+n 后置复核退化为对既有行的纯校验，语义空洞）。若应允许为 no-op，需改。
3. **applied_seq 的推进职责**：现读法=投影器推进（sessions 行本身是读模型根行，由投影 `py.session.created` 创建；后续事件由投影器 UPDATE），store 仅在提交前复核 A=H+n、违者整单回滚（isolate=False）。若契约意图是 store 自身维护 applied_seq（投影器只写其余读模型表），需改——两种读法下测试的 fake 投影器都要做最小 upsert，改法集中。
4. **事务本地失败不隔离**：投影器异常或忘推 applied_seq 只回滚不隔离（前置状态健康，回滚后仍健康）；仅对**已存数据**的损坏检测（A≠H/空洞/重复/非法/行缺失/存量解码失败）才走 §3.2.1 隔离。此为对"isolate 标志"语义的读法，待确认。
5. **dedupe_key 为批级**（整批同值、跨批 unique 生效）；若契约意图是事件级独立 dedupe key，需改。
6. **隔离持久化失败的调用方语义**：向调用方抛原 StorageCorrupt（IsolationPersistFailedError 经异常链保留于 `__context__`），内存写闸门仍然生效——"隔离未落库但本 writer 内提交全拒"，进程重启后靠 DB 损坏检测兜底。待确认是否需要更强的落库保证（如重试）。
7. per-session 锁注册表与内存隔离集 R1 不设上限（docstring 已注明）；长生命周期进程的回收策略留待后续裁决。
