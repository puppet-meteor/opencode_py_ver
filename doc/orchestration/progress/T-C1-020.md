## ① 方案审视发现

- **S2 m-2 撞键文案区分机制**：选**捕获后按 (session_id, request_id) 复查**（评审建议款）——`except IntegrityError` 内一条 `SELECT run_id FROM runs WHERE session_id = :sid AND request_id = :request_id`：有行=身份撞键沿用现文案（"request X is already accepted under another run for session Y"）；无行=GLOBAL run_id 主键撞车改报新文案（"run R is already accepted under another session (global run_id collision)"）。弃选方案：按 run_id 全局 SELECT 预检（会把成本挪进 happy path，每次 accepted 都多一查）；复查只发生在错误路径，O(1)。行为零变化：两源均 REASON_DUPLICATE_RUN、拒绝回滚 isolate=False。文案零测试钉定（调度器已核 0 匹配），改后由本批两测正向钉定（见②）。
