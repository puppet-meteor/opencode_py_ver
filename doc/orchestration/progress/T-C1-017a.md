**③ M-2 测机制面逐项浮报**：
- **端口竞态处理**：bind 端口 0→取号→关闭探针→使用（任务书建议形态照用）。残余 TOCTOU（关闭后至连接前他进程抢占该临时端口）理论存在、概率极低；若发生则连接不再被拒，测试会失败而非误绿。
- **计数机制**：monkeypatch 于 SDK client 的 `create()` 边界——counting 异步包装委托原方法，每次计数即一次真实 connect 尝试；`calls == 3` 直接计数初次+两次重试，绝无耗时下界推断（A §10 L387 明令遵守）；monkeypatch 仅存在于测试内、auto-restore，不侵入 adapter 源面。
- **NO_PROXY（本测必需）**：本机 httpx2 经 `urllib.request.getproxies()` 回落读 Windows 注册表系统代理（实测 ProxyEnable=1→127.0.0.1:10808，本地 VPN；getproxies_environment() 非空返回即抑制注册表回落）。不设 NO_PROXY 时死端口请求被代理应答 502/ReadError 而非 ConnectError（探针实测，脚本在 worktree 外 `%TEMP%/opencode/r2-s4a-probe/`）。NO_PROXY=127.0.0.1,localhost 双重生效；环境无代理时无害冗余。既有 fake-server 测不受影响（代理对监听端口透明转发，全量 446 绿为证）。
- **Windows 错误形态**：任务书预警的 ConnectError↔ConnectTimeout 漂移未观测到——实测稳定链路 ConnectionRefusedError→httpx2.ConnectError→APIConnectionError（cause 类名 "ConnectError"）→`_RetrySignal`（两轮探针+测试实跑一致）。代理干扰形态（502/ReadError）非竞态路径，已由 NO_PROXY 消除。
