# T-C1-049 · 席位C-1：产品级配置桥（ConfigLoader 第五层）——CLI 免显式 `--base-url`/`--api-key`/`--model`

分支 p2-s19 @`eb24cdd` 基线上的单提交（提交信 ASCII、显式路径、零 push）；工时 ~18 分钟（止损 90 分钟未触）；TDD 红先行落档（桥文件收集错误 `ModuleNotFoundError: opencode.config.product`——台账 16-err + 8 项 loader/CLI 新钉基线败；2 项 CLI 优先序钉基线即绿——基线代码已有 flag/env 面，仅「产品值到达」面红）。

## ① 设计判定

### 本票性质：第五层插入 + CLI 回退面重排（键集合零增改）

层序定谳（§3.2 钉死）：**builtin < product < global < project(root→cwd) < CLI**。产品层落 `load()` builtin 与 global 之间：`origin=f"product:{config_dir}"`、`path`=双读序末位文件（见下）、`directory=None`（**产品配置目录不是指令源**——其 AGENTS.md 不进指令链；AGENTS.md 语义仅属 -py 自有层）、层校验 `_validate_layer_keys(host_tier=True)`（endpoint/api_key 本就是 `HOST_ONLY_KEYS` 既有键、model 本就在 `_KNOWN_KEYS`——**零键集合增改**，产品层恰携带三既有键 `{endpoint, api_key, model}`，外语配置其余键 theme/keybinds/mcp/autoupdate 等一律忽略不进层值不报错）。无产品文件时 `resolve_product_values`→None，层静默不建，层链恰原三段（loader 钉 `test_no_product_config_keeps_the_original_three_tier_chain`）。

### product.py 纯函数面（零副作用：不写 env 以外的全局态、不打印）

- `product_config_dir(explicit: Path | None = None) -> Path`：`explicit`（测试注入口）> `$XDG_CONFIG_HOME/opencode` > `Path.home()/.config/opencode`。
- `resolve_product_values(config_dir: Path) -> dict[str, object] | None`：双读 `opencode.json`+`opencode.jsonc` 浅合并（jsonc 键覆盖 json；jsonc 先剥 `//` 行注释与尾逗号——`_strip_jsonc` 为 T-C1-048 `_maas_real_config.py` 扫描器移植：字符级转义状态机+逗号悬置回看，**string-aware**——URL 内 `//` 与字符串内逗号不腐蚀，两钉在案；该 helper 文件本票零触碰）。全缺席 → None。
- 结构面：provider 块名 env `OPENCODE_PY_PROVIDER` 缺省 `"gateway"`；块内 `baseURL`/`apiKey` 平铺或 `options` 嵌套两形皆读（本地网关文件为嵌套形）；model=块 `models` 映射**首键**。**不读 `auth.json`**（钉在案）。
- 错误面 fail-closed、命名缺失件、**零值回显**：文件在但非合法 JSON → `ConfigError("product config <name> is not valid JSON")` 形；provider 块缺席/非对象/baseURL 缺损/apiKey 缺损/models 空映射 → 各自命名 ConfigError，消息不含已读值（5 错误面全钉）。

### 产品层 path 规则（票面「实际贡献值的文件」的落钉裁定）

`path` = 双读序**末位文件**（jsonc 在则 jsonc，否则 json）——「合并值所应答的文件」（jsonc 键覆盖 json，故合并值对末位文件负责）；代码注释+loader 钉 `test_product_layer_shape_origin_path_directory` 双处载明。

### 循环导入解法

`product.py` 模块级 `from opencode.config.loader import ConfigError`（错误类型归属 loader 既有面）；`loader.py` 两处**函数内惰性 import** `opencode.config.product`（`__init__` 缺省目录解析 + `load()` 取值）——反向模块级导入会成环。

### CLI `_parse_arguments` 重排（§3.3；main() 零改动）

env 回退（原形）→ `ConfigLoader.load()`（提前）→ 凭据回退 `args.base_url = args.base_url or values.get("endpoint")`、`args.api_key = args.api_key or values.get("api_key")`（字符串真值校验）→ 仍缺 `parser.error` 三源命名文案（`--base-url is required (or set OPENCODE_PY_BASE_URL, or supply 'endpoint' in the product/global config)` 形，api_key 对称）零值回显。model/context_limit 校验行**零改动**（model 面原已走 `values.get("model")` 回退——第五层自然供及，CLI 免显式 `--model` 免费获得）；main() 凭据全部出自 args 故零改动（e2e 钉 `test_cli_runs_e2e_three_flag_free_on_product_config` 证主循环免三旗标走通）。三旗标 help 文本刷新（提及产品配置回退）。
