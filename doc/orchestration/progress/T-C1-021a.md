## ① 方案审视（缓存设计 + 完整性校验选型）

**缓存载体**：`SessionProjector` 实例内 `dict[session_id -> _FoldCacheEntry]`（`last_seq` / 折叠态 `state` / `digest`），懒分配（无 `__init__`——冻结测试文件里的 `FailingProjector`/`NoAdvanceProjector` 自带 `__init__` 不调 super，加构造器必炸存量测试）。R2 事件命中条件：`entry.last_seq == event.seq - 1` 且前缀链校验通过；`py.prompt.accepted` 面在结尾保温扩展（多 run 会话不冷启动）；`py.session.created` 面与 S8 rebuild 面不接触缓存（rebuild 走 txn.py 自有折叠，`_projector.apply` 唯一调用点是 `_insert_and_project` L684，亲核）。

**完整性校验载体选型：累积 digest 链（blake2b-256，长度前缀字段序列化，无分隔符歧义）**，覆盖 `_replay_state` 送入解码器的全部原始列（session_id/seq/id/type/version/created/data/metadata）。每次 R2 投影把存储前缀整段重读一遍并重算链（`_verify_prefix`）：命中=逐字节未变→单次折叠新事件；未命中/无条目/seq 断档→退回全量解码+折叠重放（并重建缓存条目）。**选型理由**：③-9 语义要求"篡改在下次提交必被检出且错误钉 id/seq"——逐段重验（只验近期段）会让老行篡改漏检，等价削弱语义；累积链保证任意前缀行哪怕 1 字节同长度改动都断链→回退全量重放→由既有解码路径抛出**逐字节相同**的 `stored_event_decode_failed`+details 钉行。链在提交事务内用**读回行**（`_SELECT_EVENT_AT`）延伸，而非内存事件序列化——下次提交校验比对的正是真实落库字节。误报代价为零（断链仅多付一次全量重放），跨库/跨实例的条目污染同样被链比对拦截（内容不同→断链→重放自愈）。

## ③ 浮报清单（未测/协议不可达防御分支——本次改动面）

1. `_chain_event_row` 行缺失→`None`：写者整批先插后投影（txn.py L677→L683），同事务读回不可缺；fail-open 仅跳过缓存更新（下次事件走全量重放），不吞投影错误。
2. `_remember_fold_state` 仅在折叠+写行全成功后调用：中途任何 StorageCorrupt 异常路径不更新缓存（条目停在批前状态，seq 断档下次必 miss）。
3. `_extend_fold_cache_after_r1` 吞 `IllegalTransitionError/ValueError` 并弃条目：可达面仅 (a) 全量折叠与 prompt 面行级预态折叠合法域不同 (b) 条目跨库陈旧污染；两种都由下次 R2 事件的全量重放自愈/复现既有语义，未设跨库构造测试。
4. 命中路径跳过旧行解码的等价性：锚两条协议不变量——(a) digest 链覆盖解码器消费的逐字节列，链等即前缀字节等即解码确定等；(b) 写者以同一模型实例序列化落库并传投影器（round-trip 恒等，同事务读回链入真实落库字节）。无构造性测试（对抗性"同字节异解码"在纯函数下不存在）。
5. 批回滚后的陈旧条目：日志 high 回退到 `last_seq` 之下 → 命中算术（`seq == last_seq+1`）不可达 → 下次全量重放；存量回滚测试的故障 projector 整体覆写 `apply`，不进入缓存路径，故无专门断言。
6. `_CountingProjector`（新增测试侧子类）自带 `__init__` 不调 super——基类无构造器故合法；此模式与存量 `FailingProjector` 同构。
