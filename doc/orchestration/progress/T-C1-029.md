## ① Selection rationale

- **Wire name `bash__run`** (namespace `bash`, name `run`): the `bash` namespace is already
  in the frozen `_ASK_NAMESPACES` default table (`tools/policy.py` L77-78), so every call
  asks by default with **zero policy.py edits**; `extract_resources` binds the full
  `command`/`cwd` pair (S2-frozen input-key convention — the schema uses exactly those
  keys, not TS's `workdir`).
- **Explicit interpreter, never `create_subprocess_shell`** (§5.3 L276): argv is always
  `[executable, *interpreter_args, command]`. Windows: `pwsh` preferred, `powershell`
  fallback (contract names PowerShell; no gitbash/COMSPEC guessing). Unix: `bash` via
  PATH probe + `/bin/bash`. Availability is probed by a real spawn (`--version` /
  `-Command exit 0`), cached for the process lifetime; unavailability produces an
  install-guidance diagnostic (rg precedent), never a silent fallback.
- **Windows tree reaping = Job Object via ctypes** (OP-R3-9): the spawned pid is assigned
  to a job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; timeout/cancel calls
  `TerminateJobObject`, and closing the handle is the kernel backstop. Chosen over
  `taskkill /T /F`: atomic (no child-enumeration race between spawn and kill), and the
  close-on-job-close flag reaps even children the scheduler never saw. Unix:
  `start_new_session` + `os.killpg(SIGKILL)`.
- **§5.3 L277 run discipline**: 120 s default timeout (TS `shell.ts` L24
  `DEFAULT_TIMEOUT_MS = 2 * 60 * 1_000`, zero deviation), `0` disables; 64 KiB per-stream
  output cap with a byte-exact truncation marker + original size while **both pipes keep
  draining** (no flood deadlock); streams stay separate (deterministic; TS's pty merge
  rejected); the exit code is **data** (nonzero → `succeeded` + "Exited with code N"
  notice + `structured_output.exit`), timeout → `TOOL_TIMEOUT`, cancel →
  `EXECUTION_UNKNOWN` — the Invoker (frozen, L1092-1158) maps all of these to the
  §2.1 L35 failed/unknown terminal for side-effecting tools, which is the honest
  conservative mapping (a killed command's effects are not provable).
- **Deny set (OP-R3-2)**: 5 advisory regexes (rm recursive-root deletion, fork bomb,
  `mkfs`, Windows `format`, `dd of=/dev/`). A hit prepends a warning to the result and
  **never blocks** — §5.3 L276 last sentence: a dangerous-command regex cannot prove
  safety. The TS `shell/scan.ts` 2409-line lexer is deliberately not ported.

## ④ Mandatory disclosures (frozen-surface constraints, honestly held)

- Pre-assignment race: if the child exits before `AssignProcessToJobObject`, assignment
  fails and the job backstop does not cover that child; the run surfaces this through the
  not-reaped → `EXECUTION_UNKNOWN` path instead of fabricating success.
- Unix `killpg` can race PID reuse / leave zombies until the parent reaps; same
  `EXECUTION_UNKNOWN` honesty applies.
- Interpreter-unavailable and missing-`cwd` diagnostics land **after** `py.tool.started`
  is committed, so the frozen Invoker maps them to `failed`/`unknown` (§2.1 L35
  "adapter-proven, else unknown"). A sharper `not_started` is not expressible through
  the frozen surface — disclosed, not worked around.
- When `cwd` is omitted the policy binds the resource key as `(command,)` only —
  an always-decision then covers that command in any working directory.
- The subprocess inherits the full `os.environ` (plus the four TS marker variables);
  a hostile environment propagates to children by design (TS parity), not sanitized.
- The deny regexes have false positives and false negatives; they are advisory only.
- Output cap is 64 KiB **per stream** with line-granular truncation: a line crossing the
  cap is cut byte-exactly at the boundary (the 200 001-byte test pins 65 536 shown).
