## ① 方案审视发现（实现决策 + 接缝读法）

1. **单文件**：runner 收口为单文件 `session/runner.py`（TS `runner/step.ts`/`max-steps.ts`/`retry.ts` 三模块折叠为一个协程状态机；S6 无并发分片需求，state machine 内聚即文档）。
2. **EventCommitter/sink 组合顺序**：commit（读 `repos.log_high` 于 per-session `asyncio.Lock` 下）→ `store.commit` 单写入口 → `bus.notify(seq 序)`；`sink = commit` 的 Invoker EventSink 面 —— 工具事件与运行事件同一存储/总线路径，无第二写者（③-24）。ConflictError 有界重试 3 次（同 drafts + 同 batch id，全批幂等）。
3. **状态读取策略**：每 step 顶部 `_load_state`（EventLog 分页折叠全量，log 即唯一真相 §3.3）；运行中不做内存缓存状态；`cancel_event` 仅协作快路径（§7 L335），一切终态决策由折叠态驱动。`_active_steps[run_id]=(model, started_at)` 是 step.started→step 关闭之间的单飞簿记（非折叠态），`_finalize_interrupted` 消费并断言存在。
4. **EOF/error chunk 分派**：error chunk → verbatim 携带 + interrupted（finish 后到达 error → error 赢，fail-closed 浮报）；EOF 无终态 chunk → 合成 `PROVIDER_STREAM_INTERRUPTED`（retryable=True）；UsageChunk last-wins、FinishChunk first-wins。
5. **限额执法点**：三限额（text 流/参数/调用数）在 `_consume` 内联执法（§5.3 L276 明文"generation-level"）——violation 即 `_GenerationViolation` → `_fail_generation`（step.finished failed 空 parts + run.finished failed 一批），不提交任何 finalized、零工具执行（§3.1 L142 保存收文只属取消，violation 丢弃）。text 限额保守地把 reasoning 计入同一累计（浮报）。
6. **取消三路径**：(a) 预分支（ACCEPTED+CANCELLING）→ 不发 run.started 直接终态 interrupted；(b) 软信号（durable cancel + `cancel_event.set()`）→ `_run_tools` 每 tool 前查信号、StoreError 竞态重读态 → `_finalize_interrupted`；(c) 硬取消（CancelledError）→ `_consume` except 分支 best-effort 提交已收文（catch StoreError: pass）→ `run()` 顶层 except 重读态，仅 CANCELLING 才终态化后 re-raise（非取消性硬取消留开放 step 给恢复协调者，浮报）。mid-stream 取消无需特判：generation batch 从 CANCELLING 折叠合法，tool 循环自行纠正。CoreErrorCode 注册表封闭无 CANCELLED 码（§8）→ 用户取消的 interrupted 终态 error=None（step message 与 run.finished 同）；流中断类才携带 error（EOF 合成/verbatim）。
7. **取消态下的 run.finished 合法集**：`failed` 从 CANCELLING 折叠合法（`_RUN_FINISH_OUTCOMES` §2.1 L59-61）→ max_steps/violation 类失败在取消竞态下仍可落 failed；`succeeded` 不合法 → 唯一改判 interrupted 的路径。
8. **id 约定**：`step_id = step_{run_id[4:]}_{n:04d}`、`execution_id = exec_{run_id[4:]}_{n:04d}_{call:04d}`、`request_id = req_{run_id[4:]}_{n:04d}`（每 step 一个；GenerationRequest.request_id 无 pattern 约束）；事件 id/batch id/message id 走注入 IdFactory。
9. **finish-reason→step 终态映射**：任何 finish reason 都 `completed` 收口 step（TS step.ts Outcome）；**needsContinuation 由 tool parts 存在性驱动**（无 tool part → run succeeded；有 → 下一 step）。
10. **`_wire_tool_name`**：点分 `ns.name` → wire `ns__name`（首点 partition），与 `maas.tool_wire_name_from_dotted` 语义镜像但内联（runner 保持 provider-agnostic，不 import 具体适配器）——实现重复为浮报。
11. **④-5 跨响应 tool_call_id 查重**：`_history_call_ids(state)` 扫折叠历史全部 AssistantToolPart（§2.1 L37 身份不跨响应回收）。
12. **④-8 非对象参数**：`AssistantToolPart.input` 线面为 JsonObject，非对象 JSON 无法表示 → `tool_arguments_not_object` generation 失败，零工具执行（不猜测成型）。

## ③ 强制浮报清单

- **协议不可达**：`run.finished(succeeded)` 从 CANCELLING 折叠非法（§2.1 L59-61）→ step.finished 与 run.finished(succeeded) 之间的取消竞态走 except StoreError 重读 → 改判 interrupted；`run.started` 提交撞上先行 cancel_requested（accepted→cancelling 使 run.started 非法）同样重读改判。`tool.requested` 撞上同窗 cancel → StoreError 重读 → CANCELLING 则终态化。三类竞态窗口均极窄（单进程同 loop 内 EventCommitter 锁下多数已被串行化），测试未逐窗构造（多写者需第二提交者），语义由折叠合法性保证——浮报：**未测协议性竞态路径**。
- **未测防御**：`EventCommitter.commit` 的 ConflictError ×3 重试（单进程 per-session 锁下无第二并发写者可触发）；`_finalize_interrupted` 的 `assert entry is not None`/`assert existing is not None`（折叠不变量）；`run()` 对未知非 CANCELLING StoreError 的 re-raise 路径（存储真故障）；`execution_id` 冲突（同 step 内 `_plan` call_ordinal 单调 + step 内 tool_call_id 唯一已排除，跨 step 由 step_id 前缀排除）。`part_id_reused` 防御性加入（规范未列，chunk 面可表达）。
- **已测防御**：四类 generation violation 零执行、三限额、跨响应查重、取消三路径、硬取消收文、单飞簿记消费。
- **架构注记**：`_wire_tool_name` 与 `maas.tool_wire_name_from_dotted` 实现重复（aggregation 层与 adapter 层各持一份映射，接口冻结不改 maas）；text 限额把 reasoning 计入（保守读法）；`_fail_generation` 不保存收文（§3.1 L142 文义只覆盖取消）；mid-stream durable cancel 后 generation batch 合法落地（step 已 RUNNING，取消只封新 step/tool）；error-after-finish → error 赢。**测试期实修**：`_interrupted_message` 起初按 pre-batch 折叠态重建 tool parts，与同批先行的合成 tool.finished 折叠分歧 → IllegalTransition/StorageCorrupt；改为 `synthesized` 终态表传入（synthetic 取合成事实，已终态取折叠事实）——集成测试捕获的真实缺陷。
- **存量缺口（非本席位）**：`ReadRepositories.messages()` 仅解码 UserMessage（R2-S8 分页消费者将受影响）；`R2-S4-review.md` 不存在于 worktree（S3/S5 有）。
