**`src/opencode/session/projector.py`**（新增，真实读模型投影器）
1. `SessionProjector`：结构化实现 S3 `Projector` Protocol（`async apply(connection, event)`，不显式继承）；全部过渡规则经 `state.apply` 折叠（**零内联**——AST 测试钉死 import `opencode.session.state`）；同一折叠供 S8 rebuild 复用。
2. `py.session.created` → INSERT sessions 行（status=active、canonical config_snapshot JSON、snapshot_hash、applied_seq=事件 seq）；`IntegrityError` → `StorageCorruptError` reason `duplicate_session_projection`（TS `SessionEvent.Created` L541-568 onConflictDoNothing+SessionAlreadyProjected 的 Python 映射）。
3. `py.prompt.accepted` → 先 SELECT 会话行：无行 → reason `prompt_accepted_without_session`（最保守口径）；未知 status → reason `unknown_session_status`；折叠后 INSERT messages 行（message_id=内嵌 UserMessage.id、seq=事件 seq 对齐 TS insertMessage L481-504、data=完整 UserMessage canonical JSON）；`IntegrityError` → reason `duplicate_message_id`；随后 `_advance_applied_seq`（独立方法=故障注入缝：NoAdvanceProjector 复测 store 复核 A=H+n）。
4. 投影器全部失败 `isolate=False`：均发生于健康前置状态（store 写闸门已先行拒绝非 active 会话），坏批整批拒绝+回滚，不隔离；隔离职责留在 store 对存量数据的检测（§3.2.1）与 S8。错误 details 全净化（reason/session_id/event_id/seq，无裸行内容）。
5. 无 Bus/无全局注册：projector 由 `SessionStore(engine, projector=...)` 显式注入（TS `bus.project` 注册模型不做，S3 既定单一写入路径）；assistant/idle 折叠未提前实现（R2）。

## ③ 未决问题

1. **working_dir 不落 sessions 行**：任务书第 2 条把 working_dir 列入 INSERT 列，但 CORE-CONTRACTS §3.2 L178 与锁定迁移 0001 的 sessions 表均无该列；working_dir 留在事件 data + 折叠态（`SessionState.working_dir`，测试断言折叠保留）。若契约意图是加列，需先改契约+迁移（越权，未做）。
2. **prompt 无 sessions 行的口径**：按最保守读法 StorageCorrupt(isolate=False)——经提交路径到达必为"批首事件非 created"（首次创建闸门豁免），其将产出的日志是过渡损坏，整批拒绝回滚；无会话可隔离、不 INSERT 最小诊断行。若应隔离（孤儿日志场景），需改。
3. **重复投影/重复 message_id 的 isolate=False**：延续 T-C1-004 未决 4 口径（前置状态健康，坏批回滚后仍健康，不隔离）；TS 对应路径为 SessionAlreadyProjected 致命错误（进程死亡），Python 映射为调用方可见的 StorageCorrupt。待 A/B 确认。
4. **N-2① 配方偏离 + S3 比较循环 JSONDecodeError 泄漏**：任务书字面配方（已提交行 data 改非法 JSON 后整批重试）实测：`_idempotent_replay` 的比较循环经 `_json_column` 直接 `json.loads` 存量 data，非法 JSON 抛原始 `json.JSONDecodeError`——不隔离、会话保持 active、零诊断；解码失败捕获（`_decode_stored`→REASON_STORED_DECODE_FAILED）在其后，触达不到。此为 S3 既有缺口（比较循环的存量解码失败未纳入 §3.2.1 检测面）；修复=在比较循环外包一层解码失败→StorageCorrupt+隔离，属 txn.py 第三处改动（超出本切片两处授权）。已按 seq=0（比较不比对 seq、由 `_decode_stored` 捕获）等价直测隔离路径。建议调度器授权后续一行级修复。
5. **N-1 无直测**：本切片测试授权仅限 test_projector.py 新增与 test_store_commit.py 两条 N-2；N-1（隔离持久化失败的异常链）需在 `_isolate_locked` 内注入持久化失败方可触达，未新增直测，留待授权。
6. **active_run_id 不推进**：R1-S4 范围仅 sessions/messages 两表投影，run 槽位占用是 S7 关注点，行保持 NULL（测试显式断言）。
7. **投影器全部失败 isolate=False**：隔离面=store 对存量数据的检测（§3.2.1）+S8 rebuild；投影期失败发生于健康前置状态，一律只回滚（延续 T-C1-004 未决 4 读法）。待 A/B 确认。
8. **"无外部调用"测试的事件循环约束**：socket 类本体不可作为 monkeypatch 封禁目标（Windows proactor 自管道 isinstance 依赖），封禁面退至 create_connection/getaddrinfo/connect 方法/子进程族；Python 一切 HTTP/TCP 客户端必经 create_connection 或 getaddrinfo，证明强度足够，但如需绝对封禁 socket 构造，须在非 Windows 循环策略下另测。
