## ① 方案审视

### 1. fold A=H 判定（票面前置门）
改动前实测：`state.apply()` 分发尾对 `PY_CONTEXT_COMPACTED` 抛 `"event type ... is not foldable"`；`SessionProjector.apply()` else 分支抛 `"event type ... is not projectable"`——两者都是**无默认推进的 fail-closed 设计**（未知事件类型既不折叠也不投影，A 不动）。判定：需要显式分支，形态 = S6 `py.skill.activated` 先例（state 携带记录、projector 推进 A、无读模型 diff）——**非架构缺口**，不触发上浮。落地：state.py L476 分发 + L1169-1230 `_apply_context_compacted`；projector.py L369-370 分发 + L512 `_project_context_compacted`。

### 2. 触发点裁定（§2.4 L128 留白）
契约只命名阈值（40 消息），不指定检查位置。裁定：**结算后**——`_drive_run`（service.py L1562-1592）在 runner 正常返回（`settled = True`）后触发 `_post_run_compaction`；取消（`CancelledError` re-raise）与崩溃（except 分支）**永不触发**。触发不区分终态 outcome（interrupted/completed 同面）——结算即门。失败策略（§2.4 L132）：引擎异常按会话记录进 `_compaction_errors`（L1350），**绝不**并入 `_schedule_errors`（run 已结算，其结局不可被 compaction 失败污染）；红线是上下文零替换、零半写。

### 3. 接线设计：有效视图物化在 fold，而非 context.py
冻结的 runner.py 以 `history=state.messages` 调 `ContextBuilder.build`——故替换必须发生在折叠产物上。设计：`SessionState` 增 `message_seqs: tuple[int | None, ...]`（每消息的落定 seq 并行元组，4 个消息处理器维护：prompt L538 / run_finished L624 / step_generated L768 / step_finished L813-833）+ `compaction: CompactionInfo | None`（L408/L412）。`_apply_context_compacted` 把被覆盖前缀替换为**恰好一条** summary `UserMessage`（id `msg_summary_{event.id}`、created_at=事件时刻、provenance 元数据 L1205-1218），保留 settling seq ≥ `retained_from` 的消息（L1200-1204，strict zip + fail-closed 链路守卫 L1191-1198）。

**summary 的 `message_seqs` 条目为 `None`**：它是替换面不是 settled 历史——保住引擎下轮读面的严格递增 seq 校验，也阻止替换后立即再触发；40/8 钉死保证两轮之间 ≥32 条新 settled，last-8 窗口必然全在上一轮之后。

### 4. service 接线与真实 settled 读面
- 构造参数 `compaction_summarizer: SummaryGenerator | None`（L492；`None` = 前 M6 休眠面，行为严格 no-op）。引擎**惰性构建**（L1267-1289）且只过真实面：本服务 store（§3.2 提交接口）、settled 读面、共享 ids/clock、`self._session_lock`（§3.2 L209：捕获/H 读/短提交锁 = 其他所有提交路径同锁）。唯一注入缝 = 模型调用（service 不持有 provider face；app.py 冻结，见 ④-1）。
- 真实读面 `settled_history`（L1291-1322）：EventLog 全量折叠 + `repos.log_high`；settled = 折叠消息中 seq 非 None 者；物化 summary **永不计入**（8 条而非 9 条，下一轮靠真实增长再触发）。缺失会话沿 EventLog 的 `NotFoundError` 面（与 service 其他读面一致——fail-visible，测试钉死）。
- notify（§3.2 L159 step 5 形态）：仅 `outcome.event is not None`（即 status="compacted"）时 `self._bus.notify(session_id, [outcome.event])`（L1352-1353）；below_threshold 与 discarded 皆 no-op——discarded 是结果不是失败，不入 `_compaction_errors`。

### 5. context.py 零改动裁定
接线不需要 context.py 任何变更（授权保留未用）：ContextBuilder 对有效视图的组装规则不变（summary 作为普通 user 消息先行、尾随 verbatim、idle 行仍按 §2.2 L243 不贡献），溢出仍诚实抛 `ContextLimitExceeded`。两面均有测试钉死。
