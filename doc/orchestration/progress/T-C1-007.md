**`src/opencode/bus/bus.py`**（新增，核心实现）
1. `VolatileBus.subscribe(session_id, types?) -> AsyncContextManager[AsyncIterator[Event]]`（契约 §4 L219 字面，Python 侧用 `contextlib.AbstractAsyncContextManager` 表达）：`_Subscription` 同时实现 async context manager 与 async iterator；**进入 `__aenter__` 才注册**（进入订阅前的通知不可见），`__aexit__` 注销并清空队列（"退出 context 注销并释放队列"）。类型过滤：`types=None` 收全部、显式集合只收所列（空集匹配零事件）、单个字符串拒绝（防按字符过滤的调用方笔误）。
2. **有界队列**：每订阅 `_queued_events` 计数 + 无界 `asyncio.Queue`，事件数达 `queue_limit` 即溢出——**不静默丢**：已接受前缀仍按序投递，随后从迭代器抛 `SlowConsumerError`（`.core` 为 §8 wire 形状，code=`SlowConsumer`，details 含 `session_id`/`queue_limit`/`event_id` + durable 才有的 `seq`，定位首个未投递事件），订阅即刻注销（后续 notify 既不抛错也不入队），错误只抛一次、之后迭代器 `StopAsyncIteration`。**notify() 对慢消费者永不抛错**（commit 已成功，通知面不得反噬提交路径）。健康的并行订阅者不受慢消费者影响（快照迭代 + 终止后跳过）。
3. `notify(session_id, events)`（对齐 TS bus.ts L496-509 的通知面，Python 只保留 live/typed 两面）：按调用方给定顺序投递 committed durable + ephemeral；**同一 notify 调用内按 event.id 去重**（"同一 notify 调用内不重复投递"）；事件归属校验（session_id 不符即 ValueError）；可选注入 `EventRegistry`（S1）时 fail-closed 校验类型且**先验证后投递**（坏批零投递，durable 按 (type,version)、ephemeral 按名、错面报 `UnknownEventTypeError`/`DurabilityMismatchError`）；未注入时信任组合层。**Bus 零持久状态**：无 durable cursor、无重放、无任何 DB import。
4. `Event = DurableEvent[Any] | EphemeralEvent[Any]` union 别名定义在 bus 模块并文档化（契约无统一 Event 别名）；TS 差异按任务书执行：无 location 路由（bus.ts L729-749）、无 deprecated listen/project（`test_volatile_bus_has_no_dropped_ts_surfaces` 断言不存在）。

## ③ 未决问题

1. **队列上限选值 = 1000（`DEFAULT_QUEUE_LIMIT`）**：契约 §4 只钉死"有上限+溢出断开报 SlowConsumer"，未给数值。选 1000 的理由：① 一次生成批次的事件量（committed durable 批 + 流式 ephemeral 突发）典型为几十至数百，1000 留约一个数量级余量，让跟得上的 UI 订阅者永不误伤；② 每事件是小 pydantic 信封，1000 封顶个位 MB 内存，停滞订阅者不会无限滞留事件（TS `PubSub.unbounded` 正是被 §4 否决的形态）；③ 溢出即 SlowConsumer → 订阅者重订阅 + S6 EventLog 补读，余量大小不影响正确性只影响误伤率。工程选值非契约值，构造器 `queue_limit` 可按部署调整。
2. **SlowConsumer 交付语义选型**（契约只说"溢出断开并报 SlowConsumer，不静默丢 durable"，未定义已入队事件去向）：取最保守读法——**已接受前缀仍按序投递**，溢出事件本身及其后通知不再投递且在 details 中定位首个未投递事件；若审查裁决"溢出即立刻断流、丢弃已入队事件"，仅改 `_offer` 的 sentinel 入队时点（一处）。
3. **`retryable=False`**：§8 未逐码定义 retryable；该订阅已终局断开、"重试同一操作"不可行（恢复=新订阅+EventLog 补读），取 False 保守。调度器若按"工作流可重试"裁决为 True，一行可改。
4. **seq 顺序由组合层保证**：L159"按 seq 发 Bus 已提交通知"落在调用方（`SessionStore.commit` 返回值本身按 seq）；Bus 按给定顺序投递、不重排（durable/ephemeral 混合批无良定义的重排键），bus.py docstring 已注明该调用方契约，联测已验证端到端 seq 序。
5. **`types=()` 取"匹配零事件"字面语义**（而非"空=全部"）；订阅过滤器不做注册表校验（允许订阅尚未注册的未来类型）；notify 的类型校验仅在注入 registry 时启用，未注入时信任组合层（store 已在提交时校验 durable）——S7 定式注入时自然获得 fail-closed 面。
6. **程序性参数错误用 ValueError**（queue_limit/session_id/types/跨会话事件归属），未新增 BusValidationError wire 类，避免与 §8 重复决策；S7 组合层可映射为 ValidationError。`SlowConsumerError` 是 bus 模块唯一带 §8 wire 形状的错误。
7. **同一 notify 调用内按 event.id 去重**（首个出现生效）——"同一 notify 调用内不重复投递"的最强读法；合法调用下无行为影响。
8. **`subscription_count` 只读属性**：契约未要求；测试与可观测性所需的最小暴露面，供调度器复核时裁决是否保留公开。
9. **无契约矛盾**：实现与 §4 L219-220、§3.2 L159 步 5、§8、r1-slices L109-119 逐条对齐，无发现冲突项。
