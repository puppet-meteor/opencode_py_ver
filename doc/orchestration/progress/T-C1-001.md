## ① 方案可执行性审视发现（B 方案疑点/缺口）

1. **pydantic 前移冲突（已由调度器裁决）**：B 方案把 pydantic 依赖列在 R1-S2（"pyproject.toml 增加 alembic/sqlalchemy/aiosqlite/pydantic 依赖"），但 S1 的 wire model 本身需要 pydantic。调度器已批准前移；按授权以 `uv add "pydantic>=2"` 完成（解析为锁文件中已存在的 2.14.2，pyproject +1 行依赖、uv.lock 仅根包依赖表 +2 行）。B 定稿时应同步修订 S2 的依赖清单。
2. **EphemeralEvent 无 R1 生产类型**：B 方案 S1 交付 EphemeralEvent envelope，但 R1 事件子集只有两个 durable 类型；§3.1 的 ephemeral 类型（py.text.delta 等）属 R2 流式链路。实现取舍：envelope 与注册表机制就绪，生产注册表（`R1_EVENT_DEFINITIONS`）只含两个 durable 定义，ephemeral 解码路径用测试本地定义覆盖（证明"加类型=加一行"的机制）。B 若期望 S1 就注册 ephemeral 类型，需要明说。
3. **CORE-CONTRACTS §1 的"JSON Schema"产出未入 S1 验收**：§1 要求"每个切片产出真实类型和 JSON Schema"，但 B 的 S1 验收只列 JSON fixture（正/反例）。本切片按 B 验收执行（fixtures 即契约证据）；是否需要额外落 JSON Schema 文件（及落点）请 B/A 补充定义。
4. **metadata run_id 规则的落点**：CORE-CONTRACTS §3.1"运行内事件 metadata 必须含 run_id"未在 B 方案出现。已在 envelope 层实现：`RUN_SCOPED_EVENT_TYPES = frozenset({"py.prompt.accepted"})`，缺 `metadata.run_id` 即 ValidationError；R2+ 新类型加入该集合即可。若 A 席 T-A-002 的 prompt 契约裁决改变该集合，按修订任务调整。
5. **config_snapshot 按 T-A-002 裁决（§6.1/§6.2）对齐**（裁决在本切片中途合入，当场消化）：
   - `ConfigSnapshot` 字段全集精确为 `schema_version: Literal[1]` + `permission_rules: list[JsonObject]`（`max_length=0`，即必须为空）；两字段必填（无默认值）、`extra="forbid"`——**hash 不内嵌快照**，摘要只存在于事件 data 的 `snapshot_hash`；
   - `schema_version` 为 Literal[1]：拒绝 2、字符串 "1"、null；`True` 因 bool 是 int 子类可骗过 Literal 相等判断，已加显式 before-validator 拒绝（§6.1"不接受布尔版本号"）；R3 可执行快照须用新 schema_version，版本 1 解码与旧 fixture 保留；
   - `compute_snapshot_hash(snapshot)`：先过 schema 验证，`canonical_json`（sort_keys、`":"`/`","` 分隔、`ensure_ascii=False`、`allow_nan=False`）→ UTF-8 → sha256 hexdigest（64 位小写、无前缀）；R1 规范文本恒为 `{"permission_rules":[],"schema_version":1}`，摘要 `77c932c3…f802` 已在测试中钉死常量；
   - 解码路径每次重算摘要并与 `snapshot_hash` 核对，不符即 ValidationError（§6.2.3"读取时重新验证"）；`_load_envelope` 的 JSON 解析按 §6.2.1 拒绝 NaN/Infinity 常量与**重复对象键**（object_pairs_hook，不 last-wins）；
   - working_dir/事件 id/时间/metadata 不参与摘要 ✓（算法天然只序列化快照对象本身）。
   - 遗留小项：§6.2.1"非法 Unicode（含孤立 surrogate）"拒绝——R1 快照无字符串字段，值域上不可触发；canonical 编码遇 surrogate 会抛 UnicodeEncodeError（ValueError 子类）自然 fail-closed，未加前置扫描。
6. **Event ID 前缀**：CORE-CONTRACTS §3.1 只说 `id: str`；TS 基准（event.ts）是 `evt_` 前缀。实现保持宽松（模型层不强制前缀），fixtures 用 `evt_/msg_/ses_/run_` 前缀示范约定；是否在模型层强制请 A 裁决。
7. **UserMessage 字段范围**：按 B 清单（id/type/created_at/metadata/text）实现；CORE-CONTRACTS §2.1 的可选 `files` 未纳入（B 未列；Phase 1 非空 files 本就应 UnsupportedCapability 拒绝，属 S3 行为，wire 层 R2+ 再补）。
8. **实现口径说明（供 B 审查）**：未知 type/未知 version/耐久性错配/坏 JSON → `EventDecodeError` 家族（显式异常，S4/S6 映射 StorageCorrupt）；缺字段/非法值/非法扩展 → pydantic ValidationError。两路都拒绝且不静默，但异常类型不同，测试按此断言。
