- **fold 规则**：requested 门=活跃 session+PENDING 工具+`input_hash` 匹配+全新 permission_id+每 execution 至多一个审批+run RUNNING+envelope run 匹配；replied/closed 要求 PENDING、首次提交即胜（§7 L173 终态一次）、closed 后迟到回复拒绝（§5.2 L268"实际 reject 才写 replied"语义外延）；saved=全新 decision_id、session 域、`boot_id` 仅事件侧；revoked/expired 经共享 `_terminate_decision` 终态一次。工具终态↔权限终态之间**不设跨实体不变量**（生产者纪律，S2 产出方负责成对——浮报③）。
- **事件注入形态选型**：契约层=文件形态（沿既有 fixtures 形态，18 个 JSON=6 型×{valid, missing_field, bad_extension}；`expires_at` 可空以数据模型编程反例覆盖不加文件）；集成层=冻结 R2 fixture saga 之上的 raw-envelope 手术构造器（`_permission_raw`/`_permission_draft` 逐字段改写+fresh event_id），不另建集成 fixture 文件——S1 无协议侧生产者（Policy/审批协议归 S2），手工注入为任务书明示形态。
- **projection 细节**：permissions 表无 permission_id/decision_id 唯一索引→投影前 pre-SELECT 查重（沿 accepted-run 模式），重复投影 `duplicate_permission_projection` fail-closed；诊断 session 拒绝权限写入（§3.2.1 L195-204 只读纪律）。txn rebuild 删权限行后重投影（sessions 行 CASCADE 否则静默丢行）——commit 序（~L160）零改动，重投影范围解读入③浮报待裁。

## ③ 强制浮报清单（四档）

**协议不可达（S1 无协议侧生产者——Policy/审批协议归 S2）**：
- `py.permission.*` 全六型均无真实生产者路径；replied/closed/saved/revoked/expired 仅手工注入覆盖（注入构造器+fold 纯函数面），requested 的 §5.2 L266"工具请求挂起时发起"由 store 级钉定（计划中 PENDING 门+锚 A/B 反证）但无 Policy 发起方。S2 需回补真实生产者链。
