### 三假说证实/证伪
- **(b) src 终态序异常——证伪**：终态写入与 runs 表可见性同事务原子（projector 内嵌 store.commit、bus 注册故意缺位）；锚轮询读同一 runs 表——「锚见 running 于终态提交之后」不存在构造。锚返回 "running" ⟹ 当刻终态必未提交。
- **(c) src 读竞态/折叠异常——证伪（主证）**：WAL 读滞后不超前 ⟹ 快径幻影终态不可构造；StoreError-crash 副候选需真实 store 故障而两份红档零证据（无 store 报错行、无 5xx 簇可辨痕迹、rerun 零现、本地多轮零现）。诚实声明：**仅凭日志不可 100% 排除**该副候选；但 (a) 机制零故障参与、负载形状逐点吻合、且恰是四环链未检之窗——优势证据归 (a)。
- **(a) 测试同步锚弱——证实（根因定谳）**：CI 负载撑宽 pre-park 窗至 10ms 轮询可命中 → 锚在 run task 尚未泊流时命中 "running" 返回 → 测试并发发 9 cancel → 首 cancel 的 intent 先落（runs→cancelling）→ run task 醒于 L503/L541 命中早折叠窗 → interrupted 终态提交、**gate 永未到达**、run task 出册 → 8 个 `await task` 泊位者随 task 终结齐返 200 interrupted + 第 9 个 429 → 1s 窗内 done=9 → `assert (9 == 1)`。本地/重跑窗口亚轮询尺度不命中故绿。**关键修正**：前序链「9-done 需要 run 在 cancel 到达前已达终态」前提不完整——done=9 不要求终态先于 cancel 到达；cancel 自身经设计内竞态触发早折叠即达同形。

### 根因定谳链
run.started 落表（锚命中）→【负载下 pre-park 窗：L503 读/L541 写】← 9 cancel 插入、intent 先落（cancelling）→ run task 醒于步顶或 step.started 被拒 → 设计内早折叠（interrupted 终态）→ gate 未达、task 出册 → 8 泊位齐返 + 1×429 → done=9 → 红。零 src 故障参与；红是**测试锚弱暴露的设计内合法行为**，非 src 异常。
