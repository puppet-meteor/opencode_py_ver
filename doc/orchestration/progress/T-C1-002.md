## ③ 未决问题

1. **构造/解码不对称（version 字符串）**：直接 `EventDraft(version="1")` 会经 pydantic lax str→int 强转成功，而解码路径（`decode_durable` 前置 `isinstance(version, int)`）拒绝 `"1"` → `EventDecodeError`。§1 只强制 bool 拒绝；本切片未收紧构造路径的 str 输入（会改变 API 容错性，超出 M-1 范围）。若期望两侧一致（构造也拒非 int），需 A/B 裁决后加任务。
2. **孤立 surrogate 前置扫描未加**：R1 快照值域（`schema_version: Literal[1]` + 空规则）无字符串字段，值域上不可触发；canonical bytes 的 UTF-8 编码对 surrogate 天然抛 UnicodeEncodeError（⊂ ValueError）fail-closed，已钉死测试。若后续快照版本引入字符串字段，考虑在 canonical_json 前加显式扫描以便错误信息更友好。
3. **metadata.run_id 的严格范围**：按任务书"whenever present must match ^run_"实现为"任何事件类型上出现 run_id 键即校验前缀"。这比"仅 run-scoped 类型校验值"更严格；若 A 认为非 run-scoped 事件上的 `run_id` 键应放行不校验，需回退该分支（现行为更保守）。
4. 前缀 pattern 为无锚点歧义写法（`^evt_` 只锚开头，尾部自由）——与 §3.1 字面一致（`^evt_`）；若期望完整格式（如定长）待未来裁决。
